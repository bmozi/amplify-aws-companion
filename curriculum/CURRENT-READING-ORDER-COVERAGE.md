# What the current field guide teaches

Use this map with the [34 chapter outcomes](../reader/BOOK-LOCATORS.md#book-b15b8fcb83e64495) and the [reading order](../reader/BOOK-LOCATORS.md#book-a7a036b8c70960b4). It describes the **current manuscript**, not a proposed book plan or a catalog of every AWS product. Each stage begins with a customer or operator decision, introduces relevant AWS capabilities, and asks what evidence would justify the result.

| Reading stage | Chapters | Question the reader learns to answer | AWS capabilities used as examples | Practice and evidence boundary |
| --- | --- | --- | --- | --- |
| Start with the system and its boundaries | 1–5 | What must happen for one customer request, who may act, where can it go, what runs it, and what can the business afford? | IAM, VPC/DNS, API Gateway, Lambda, EC2, containers, storage and database choices | Trace a request, name a denied path and estimate a bounded run. Paper and local work do not prove deployed access or cost. |
| Understand the first app and control its changes | 6–10 | Which Amplify parts serve the promise, who owns each resource, how are environments separated, and how is data protected? | Amplify Hosting/Backend/libraries/UI, Cognito, AppSync, DynamoDB, S3, Lambda, Terraform, KMS and security findings | Follow a private note and a cross-user denial; inspect ownership and change plans. Existing local checks do not prove live tenant isolation or publication. |
| Choose and operate the data path | 11–13 | Which storage/database shape fits the work, and which read can be stale? | S3/EFS/EBS, relational and NoSQL databases, caches and replicas | Compare candidates, identify the authoritative record and explain recovery from a stale or lost read. Selected AWS behavior and workload costs need separate verification. |
| Observe, release and recover | 14–18 | How does an operator detect customer harm, change the system, investigate failure and demonstrate recovery? | CloudWatch, logs, metrics, alarms, SNS, deployment controls, backups and resilience mechanisms | Define a customer signal, review a release and design a bounded recovery experiment. A configured alarm or backup alone does not prove notification or restoration. |
| Build durable customer workflows | 19–25 | How are accepted work, reservations, files, tenants, approvals, events and reports kept truthful when replies disappear or actors repeat work? | SQS, EventBridge, DynamoDB, S3 and application authorization patterns | Run selected local failure and reconciliation cases, then change a business promise. These fixtures do not establish cloud concurrency, real identity or a business result. |
| Operate across platforms and shared boundaries | 26–31 | When do containers, migrations, accounts, hybrid networks, quotas or authorized retrieval change the design? | ECS/EKS, migration tools, AWS Organizations, hybrid networking, regional service limits and retrieval integrations | Compare bounded architectures and failure paths. Organization-dependent examples remain design-only in this course. |
| Defend an architecture and practice the decision | 32–34 | Can the reader explain a choice, revise it when a constraint changes and distinguish an exam answer from operational evidence? | Services from the earlier stages, selected by requirement | Original scenarios and assessor material test reasoning locally. Independent learner transfer, full certification coverage and live outcomes remain unproven. |

The [closing route in Chapter 1](../reader/BOOK-LOCATORS.md#book-53ea34cc85da7761) shows the same repair request reappearing when access, lost replies, releases or growth change the decision.

This is a **decision-led AWS field guide**. It teaches how service families fit a system and how to verify an architecture. It does not imply that every AWS service is deployed, that every capability in Amplify is enabled, or that one book finishes every advanced certification objective. The [topic finder](../reader/BOOK-LOCATORS.md#book-9b24361462ef46cc) gives a second route from a question back to the relevant current chapter. The [exam-to-application route](CERTIFICATION-TO-APPLICATION.md) keeps question practice and observed implementation separate.

Use the current [chapter outcomes](../reader/BOOK-LOCATORS.md#book-b15b8fcb83e64495) to navigate the book. Treat a row number in those planning records as a row number, not a current chapter locator. The [skill and knowledge reviews](README.md) carry partial objective-level evidence and open work, not a certificate of mastery.
