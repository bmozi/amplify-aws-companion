# SAP-C02 task 4.3 target-platform review

Internal editorial review, October 19, 2026, against the transitional [official task 4.3 guide](https://docs.aws.amazon.com/aws-certification/latest/solutions-architect-professional-02/solutions-architect-professional-02-domain4.html#solutions-architect-professional-02-domain4-task3). The four knowledge points and four skills have **partial** authored teaching and changed-condition assessment. The [Unit 12 target lesson](../../reader/BOOK-LOCATORS.md#book-9fc6a96254952815), [two-phase diagram](../../book/figures/modernization-seam.svg), [five-case packet](../../examples/modernization-targets/README.md) and [separate assessor](../../examples/modernization-targets/ASSESSOR.md) are the review basis. They do not establish a selected workload's compatibility, AWS operation, current regional cost, learner performance, exam readiness or future SAP-C03 coverage.

| Point | Authored evidence | Still needed |
| --- | --- | --- |
| Knowledge 1: compute services | Unit compares a low-change EC2 target with Beanstalk's managed deployment environment and retained application/underlying-resource duties; case 1 changes image availability and team capability. | Selected OS/runtime/license support, measured traffic, scaling, patch/recovery owner and priced operation. |
| Knowledge 2: containers | Unit separates ECS scheduling, Fargate capacity, EKS Kubernetes and ECR image storage; case 1 reverses from unsupported image to maintained image and existing ECS skill. | Actual image, task/pod compatibility, health, deployment, IAM, security and cost evidence. |
| Knowledge 3: storage | Unit and case 2 separate S3 object, EBS block, EFS shared-file, FSx Windows-compatible and Volume Gateway hybrid volume contracts; changed case adds an on-site volume interface. | Client protocol/operation, concurrent writer, outage/cache, restore, performance and current charge tests. |
| Knowledge 4: databases | Unit distinguishes RDS relational ledger, self-managed EC2, DynamoDB key access and OpenSearch derived search; case 3 changes a lookup's access pattern. | Schema/version and transaction compatibility, data migration, index lag/rebuild, recovery and total price. |
| Skill 1: compute selection | Case 1 requires a deadline-aware EC2/Beanstalk/ECS choice, then reverses image and operator constraints. | Representative application build and operational acceptance. |
| Skill 2: container hosting selection | Case 1 compares ECS/Fargate and EKS only after image and Kubernetes requirements; assessor names Express Mode's image and underlying-resource work. | Selected platform rollout, patch/scale behavior, rollback and cost. |
| Skill 3: storage selection | Case 2 selects interfaces for collaborative drawings and immutable exports, then changes the office volume contract. | Real client and failure-mode tests with supported regional configuration. |
| Skill 4: database selection | Case 3 holds the ledger's relational contract while adding a separate key lookup and rebuildable search projection. | Representative queries/transactions, cutover, data reconciliation and recovery. |

All cases are fictional. The [local outbox drill](../../examples/modernization-targets/README.md#try-the-report-seam-locally) addresses the later modernization seam; it is not proof that these target services run. No AWS account was contacted or charged.
