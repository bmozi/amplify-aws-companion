# Database architecture knowledge review

Internal editorial review, October 18, 2026. Checked the nine knowledge bullets for [SAA-C03 Domain 4 task 4.3](https://docs.aws.amazon.com/aws-certification/latest/solutions-architect-associate-03/solutions-architect-associate-03-domain4.html#solutions-architect-associate-03-domain4-task3) against the retained official guide and current manuscript. All nine source-bullet digests match the accepted inventory. Each now has an individual **partial** teaching and assessment mapping. These entries do not complete the task's five implementation skills or establish exam readiness.

| Ordinal | Teaching and assessment evidence | What remains missing |
| --- | --- | --- |
| 01 — Cost-management features | Unit 04 explains cost-allocation tags, consolidated billing, and the boundary between payer visibility and member-account resources. A paper case changes shared database costs and billing access. | Owner-approved accounts, tags and permissions; verified allocation and credit treatment; current billing data and independent learner review. |
| 02 — Cost-management tools | Unit 04 distinguishes a proposed-use estimate, historical reported costs, threshold notifications and detailed recurring exports. The cases change timing, filters, missing tags and notification evidence. | Current estimate for a selected workload, live bill reconciliation, delivered alert, export/query operating cost and independent learner review. |
| 03 — Caching strategies | Unit 21 begins with a booking that can become stale, then explains cache-aside reuse, expiration, invalidation and why authoritative writes still belong at the database. The local exercise changes expiry and stale-repopulation timing. | Selected managed-cache authorization and failure design; observed cold-cache load, freshness and invalidation; current full cost and independent learner result. |
| 04 — Data retention policies | Unit 07 ties recovery retention to the failure and lookback promise; Unit 10 distinguishes application access cutoff from asynchronous object lifecycle cleanup. Database cases change corruption discovery and records retention. | Owner-approved policy, selected service limits and prices, tested restore and application reconciliation, independent learner review. |
| 05 — Database capacity planning | Unit 21 explains DynamoDB capacity units with item-size and consistency arithmetic and a changed peak. It cautions that relational CPU, memory, storage I/O, indexes, skew and retries need different evidence. | Measured successful/failed/retried workload, distribution and recovery headroom; relational sizing and priced configuration; independent learner review. |
| 06 — Connections and proxies | Unit 21 calculates application pools across process and deployment overlap, then explains RDS Proxy reuse and session pinning. A separate SQLite exercise observes cleanup and pool waiting. | Selected engine/driver session tests, actual proxy pinning/failover observations, representative load and price, independent learner review. |
| 07 — Database engines and migration use cases | Unit 25 separates engine choice from managed-service choice and compares application behavior, extensions, conversion and migration. Cases distinguish homogeneous from heterogeneous paths and require business parity. | Exact source/target versions and Region, application dependency inventory, rehearsed parity/load/rollback and migration cost, independent learner review. |
| 08 — Replication | Unit 21 teaches asynchronous read replicas, possible lag and read routing. A local writer/read-copy/historical-copy exercise shows how an accidental deletion can propagate to the read copy. | Selected engine lag, failure, promotion and routing tests; separate point-in-time recovery and business reconciliation; independent learner review. |
| 09 — Database types and services | Unit 25 compares relational and key-based access contracts, then RDS/Aurora and DynamoDB candidates against the same correctness, access and cost questions. | Current service/Region feature and price checks, representative data and workload tests, migration/recovery evidence and independent learner review. |

These mappings reuse relevant lessons that also support other objectives. Reuse is appropriate because the questions differ: for example, cache strategy concerns freshness and authority, while database replication concerns a maintained copy and its failure behavior. The cited exercises are fictional, local or design-only as described in their own scopes; no customer workload was priced or deployed in AWS.

All nine knowledge entries remain partial. The task's five skills are separately recorded in [the SAA-C03 4.3 skill review](../skill-reviews/SAA-4-3.md). Independent technical and learner reviews remain pending.
