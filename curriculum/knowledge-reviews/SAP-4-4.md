# SAP-C02 task 4.4 modernization review

Internal editorial review, October 19, 2026, against the transitional [official task 4.4 guide](https://docs.aws.amazon.com/aws-certification/latest/solutions-architect-professional-02/solutions-architect-professional-02-domain4.html#solutions-architect-professional-02-domain4-task4). Five knowledge points and five skills have **partial** authored teaching and changed-condition assessment. [Unit 12](../../reader/BOOK-LOCATORS.md#book-9fc6a96254952815), the [two-phase diagram](../../book/figures/modernization-seam.svg), [design packet](../../examples/modernization-targets/README.md), [assessor](../../examples/modernization-targets/ASSESSOR.md) and [local outbox drill](../../examples/modernization-targets/outbox_lab.py) are the review basis. Neither the diagram nor the local drill deploys AWS services or proves distributed delivery.

| Point | Authored evidence | Still needed |
| --- | --- | --- |
| Knowledge 1: serverless compute | Unit and case 4 condition Lambda on runtime, duration, concurrency, memory and downstream limits; changed synchronous-finance promise invalidates a simple async worker. | Actual function configuration, permissions, load, retry, downstream and price measurements. |
| Knowledge 2: containers | Unit and case 1 compare a worker/container path with ECS/Fargate and EKS requirements; image and operating team are changed facts. | Selected container image, platform feature/Region, deployment and recovery tests. |
| Knowledge 3: storage services | Unit and case 2 preserve S3 object versus EFS shared-file contracts while changing the on-site volume requirement; modernization does not erase file semantics. | Selected client operations, concurrent edits, outage and storage cost evidence. |
| Knowledge 4: purpose-built databases | Unit and cases 3/5 compare stable-key DynamoDB, relational Aurora Serverless and disposable ElastiCache read acceleration against ledger authority and total cost. | Data model and transaction tests, Aurora capacity behavior, cache invalidation/failure, current regional pricing. |
| Knowledge 5: integration services | Unit and case 4 distinguish SQS work delivery, SNS notification fan-out, EventBridge event routing and Step Functions orchestration; local outbox tests commit, lost acknowledgment, duplicate and reconciliation boundaries. | Selected service routing, IAM, retention, dead-letter, batch retry, order, concurrency, real side effects and observability. |
| Skill 1: find a decoupling seam | Diagram and case 4 separate slow report work from the accepted booking path; changing the response promise withdraws that seam. | Real timing/dependency measurement and owner-approved acceptance. |
| Skill 2: find serverless opportunities | Case 4 contrasts Lambda with a container under changed runtime and finance conditions. | Selected runtime and workload tests, concurrency and downstream limits, cost. |
| Skill 3: choose a container service | Case 1 requires ECS/Fargate versus EKS based on image, team capability and Kubernetes need, with repeatable scaling as a changed fact. | Actual rollout, health, security, recovery and price evidence. |
| Skill 4: find purpose-built data opportunities | Cases 3/5 test a new stable-key lookup, cacheable reads and relational capacity changes without replacing the ledger by label alone. | Representative data/query, failure and whole-life cost evidence. |
| Skill 5: choose integration service | Case 4 compares delivery contracts; local outbox failure drill demonstrates why committed work and repeatable effects need separate safeguards. | Actual SQS/SNS/EventBridge/Step Functions integration, delivery/failure tests and learner review. |

The local lab is in-memory sequential SQLite plus a list. Its six tests are narrower than SQS/Lambda semantics; [AWS transactional-outbox guidance](https://docs.aws.amazon.com/prescriptive-guidance/latest/cloud-design-patterns/transactional-outbox.html) and [Lambda SQS guidance](https://docs.aws.amazon.com/lambda/latest/dg/with-sqs.html) support the design boundary. The exercise is not an exam calibration or independent learner response. No AWS resource or credit was used.
