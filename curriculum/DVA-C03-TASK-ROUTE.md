# Developer Associate: twelve starting points and their limits

AWS organizes DVA-C03 into twelve tasks. This is a navigation and gap-finding aid, not a skill-by-skill inventory or a claim that the book prepares you for every exam question. Read the linked exercise, make your own prediction, and compare it with its assessor notes. Then name what the exercise cannot prove. The task descriptions below are paraphrases of the [AWS exam guide's development](https://docs.aws.amazon.com/aws-certification/latest/developer-associate-03/developer-associate-03-domain1.html), [security](https://docs.aws.amazon.com/aws-certification/latest/developer-associate-03/developer-associate-03-domain2.html), [testing and deployment](https://docs.aws.amazon.com/aws-certification/latest/developer-associate-03/developer-associate-03-domain3.html), and [troubleshooting](https://docs.aws.amazon.com/aws-certification/latest/developer-associate-03/developer-associate-03-domain4.html) domains, checked October 29, 2026. Consult AWS for the complete current skills and exam scope.

| Task | Practice here | A material gap to pursue |
| --- | --- | --- |
| 1.1 Application code | Predict a conflicting write in the [data contract lab](../examples/data-contract/README.md). Explain why a successful local HTTP response is not proof of an AWS integration. | Real SDK calls, streaming and managed AI service integration require separate service-specific practice. |
| 1.2 Lambda code | Trace callers through the [Lambda release cases](../examples/lambda-release/README.md), then predict the failed and unopened records in the [FIFO batch exercise](../examples/lambda-fifo-batch/README.md). | The cases are design-only; function configuration, event-source mappings, VPC access and error destinations need hands-on coverage. |
| 1.3 Data stores | Compare access patterns in the [database selection cases](../examples/database-selection/README.md). | Selecting a database is not configuring DynamoDB keys, consistency, indexes or lifecycle controls. |
| 2.1 Authentication and authorization | Compare list filtering and direct access in the [local note boundary](../examples/amplify-walkthrough/README.md#run-the-local-note-boundary), then reason through the [presigned access cases](../examples/presigned-access-review/README.md). | Forged fixture identities are not federation, role assumption, signed requests or presigned URL implementation. |
| 2.2 Encryption and sensitive data | Predict which consumer receives a rotated secret in the [secret lifecycle model](../examples/secret-reference-lifecycle/README.md). | The model does not operate AWS key management, certificates, encryption or a managed secret store. |
| 2.3 AI security | Decide whether an agent's proposed action is authorized in the [tool boundary lab](../examples/agent-tool-boundary/README.md). | An in-memory example does not implement AWS AI privacy, managed filters, isolated sessions or secure logging. |
| 3.1 Deployment artifacts | Follow a source archive through the [portability exercise](../examples/container-portability/README.md). | A companion source ZIP is not an application container image; ECR and environment-specific configuration need separate practice. |
| 3.2 Application testing | Match a failure to a test layer in the [local pipeline lab](../examples/pipeline-testing/README.md), then review the [API Gateway mock cases](../examples/api-gateway-mock-review/README.md). | Local tests are not AWS-environment tests, Amplify branch configuration or use of an AWS AI testing tool. |
| 3.3 CI/CD deployment | Sketch a release route and failure evidence in the [pipeline design exercise](../examples/pipeline-design/README.md). | The design creates no AWS pipeline or deployment; CodePipeline, CodeDeploy and rollback need service-specific work. |
| 4.1 Root cause analysis | Compare hypotheses in the [incident investigation lesson](../reader/BOOK-LOCATORS.md#book-48004aaa3a73ab7d). | A fictional incident is not a live log query, deployment diagnosis or use of an AWS AI troubleshooting tool. |
| 4.2 Observability | Trace a local request through the [telemetry lab](../examples/request-telemetry/README.md). | Local listeners and in-memory receipts do not configure CloudWatch, AWS tracing or real alert delivery. |
| 4.3 Optimization | Calculate the effect of rollout overlap on the [connection budget](../examples/connection-budget/README.md). | Arithmetic and design reasoning do not benchmark an application or configure AWS concurrency, caching or scaling. |

## Try it with Maya

Maya's note application slows after a release. Her team points at the database, but has only a complaint and a new version number. Start with task 4.1: list two competing causes and the evidence that could distinguish them. Use 4.2 to decide what a request identifier and timing measurement might reveal. Use 4.3 to calculate whether more application processes could exhaust the database connection allowance. Finally revisit 3.3: what evidence would justify a rollback, and which effects might remain after it? Record uncertainty at each step; none of these local exercises establishes the cause of a real incident.

Ask Codex to challenge your explanation with one counterexample and propose a test using fictional data. Check its service-specific claims against AWS documentation. Codex is a general assistant and its use does not demonstrate experience with AWS-specific AI tools named in the exam guide. Never paste credentials, customer data, account identifiers or state files into the prompt.

For optional cloud work, first select a scoped identity and Region, estimate the entire run, define a spending limit and reserve, identify stop conditions and a cleanup owner. The design exercises above do not require cloud spending. Organization-dependent work in this companion remains design-only. Exam task navigation, local tests and self-assessment are different from service-specific practice, independent learner evidence and a verified readiness judgment.
