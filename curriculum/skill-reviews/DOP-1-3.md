# Individual skill review for DOP-C02 task 1.3

Internal editorial review, October 19, 2026. The [official DOP-C02 Domain 1 page](https://docs.aws.amazon.com/aws-certification/latest/devops-engineer-professional-02/devops-engineer-professional-02-domain1.html) lists three separate task 1.3 skills: configure artifact repositories; configure build tools; automate EC2 instance and container-image build processes, such as with EC2 Image Builder. The ledger ordinals are editorial identifiers. This review maps all three skills as partial; repository configuration remains design-only with local identity checks, not live service configuration. The knowledge entries are reviewed separately in the [task 1.3 knowledge review](../knowledge-reviews/DOP-1-3.md).

## Configure build tools for artifact generation — skill 02

Unit 03's “Configure the tool that turns source into a release parcel” teaches the difference between a CodeBuild project and its `buildspec.yml`. The lesson walks through source revision, build image/runtime, ordered install/pre-build/build/post-build phases, selected artifact paths, project/service-role boundaries, managed secrets, cache separation, VPC network needs, logs and support-resource costs. Its hand-authored [CodeBuild handoff figure](../../book/figures/codebuild-artifact-handoff.svg) shows the build and failure paths. The [six design-only cases](../../examples/codebuild-artifact-config/README.md) and [separate assessor notes](../../examples/codebuild-artifact-config/ASSESSOR.md) cover empty/wrong artifact selection, stale or sensitive files, over-broad role, secret exposure, private-subnet reachability/cost, and CodeBuild versus a Lambda pipeline action. The existing local [static build-input drill](../../examples/local-operations/README.md#inspect-what-the-build-actually-packages) provides real local copying and ZIP checks, but it is not CodeBuild.

Current AWS documentation describes a buildspec as YAML instructions; version 0.2 is recommended; phases run ordered commands; runtime selection depends on the build image; and the `artifacts.files` selection names the generated files to upload. Buildspec secret references require the CodeBuild service role to read the selected secret. AWS also documents Lambda as a CodePipeline custom action that receives job input and reports success or failure; it should not be described as a general-purpose substitute for a build tool. See [buildspec reference](https://docs.aws.amazon.com/codebuild/latest/userguide/build-spec-ref.html), [build environments](https://docs.aws.amazon.com/codebuild/latest/userguide/build-env-ref.html), [CodeBuild service roles](https://docs.aws.amazon.com/codebuild/latest/userguide/setting-up-service-role.html), [CodeBuild security](https://docs.aws.amazon.com/codebuild/latest/userguide/security.html), [CodeBuild pricing](https://aws.amazon.com/codebuild/pricing/), and [Lambda actions in CodePipeline](https://docs.aws.amazon.com/codepipeline/latest/userguide/actions-invoke-lambda-function.html).

Coverage is partial, combining a local static packaging drill with design-only AWS configuration cases. No project was created; buildspec parsing in CodeBuild, GitHub/source connection, scoped role, secret retrieval, artifact bucket, VPC routing, build output, regional estimate or cleanup was tested. A real follow-up needs a selected toolchain/image and source revision, approved non-root build identity, exact actions/resources, safe test artifact destination, positive and negative permission checks, downstream receipt/behavior evidence, a current whole-run estimate within the account owner's chosen ceiling, an appropriate credit reserve and verified cleanup/billing. Independent technical and learner review remain pending.

## Configure artifact repositories — skill 01

Unit 03's “Choose a repository for the kind of artifact you made” compares CodeArtifact, ECR and S3 by artifact shape, consumer lookup and identity. It explains CodeArtifact domain versus repository, package upstreams and origin trust; ECR tags versus digests, mutability and lifecycle preview; and private S3 bundles, public-access blocking, ownership and version lifecycle. A shared artifact contract connects publisher, reader, trust, retention, recovery and cost. The [repository-choice diagram](../../book/figures/artifact-repository-choices.svg) shows three stores and their distinct lookup models. Six [design-only repository cases](../../examples/artifact-repository-config/README.md), with separate [assessor notes](../../examples/artifact-repository-config/ASSESSOR.md), cover package dependencies, moving image tags, public ZIP confusion, rollback retention, private-build reachability and a fictional account boundary. Separate [Terraform configurations](../../examples/artifact-repository-config/terraform/README.md) show one CodeArtifact, ECR and private S3 configuration; all three passed provider initialization and local validation with AWS provider 6.69.1, without a plan or apply. The [local artifact identity model](../../examples/artifact-repository-model/README.md) executes explicit version, overwrite-rejection, digest-mismatch and non-destructive retention-preview checks. It is a local filesystem model, not an AWS emulator. Task 1.4 remains a separate review of effective repository access permissions.

AWS primary documentation supports the service boundaries and configuration decisions linked in the manuscript: [CodeArtifact concepts](https://docs.aws.amazon.com/codeartifact/latest/ug/codeartifact-concepts.html), [repository creation](https://docs.aws.amazon.com/codeartifact/latest/ug/create-repo.html), [upstream behavior](https://docs.aws.amazon.com/codeartifact/latest/ug/repos-upstream-behavior.html), [origin controls](https://docs.aws.amazon.com/codeartifact/latest/ug/package-origin-controls.html), [ECR repository settings](https://docs.aws.amazon.com/AmazonECR/latest/userguide/repository-create.html), [ECR lifecycle policies](https://docs.aws.amazon.com/AmazonECR/latest/userguide/LifecyclePolicies.html), [S3 public access](https://docs.aws.amazon.com/AmazonS3/latest/userguide/access-control-block-public-access.html), [ownership](https://docs.aws.amazon.com/AmazonS3/latest/userguide/about-object-ownership.html) and [versioning](https://docs.aws.amazon.com/AmazonS3/latest/userguide/Versioning.html). Service pricing is linked separately and must be refreshed for a selected Region/workload.

Coverage is partial: manuscript teaching, an accessible working figure, six design-only cloud cases, three provider-validated Terraform shapes and a tested local identity model. No repository, package, image, bucket, policy or lifecycle rule was created or queried in AWS. No exact live action/resource policy, package pull/push, image scan/digest deployment, S3 version recovery, regional estimate, credit balance or cleanup was verified. A future cloud implementation needs the scoped non-root path, the selected account plan, an estimate within the account owner's chosen ceiling, an appropriate credit reserve, controlled cleanup and billing reconciliation. Independent technical and learner review remain pending.

## Automate machine and container-image builds — skill 03

Unit 03's “Turn a trusted recipe into a tested machine image” explains the Image Builder sequence with an accessible figure: versioned base image and components, build infrastructure, build, validation, image capture, fresh-image test, and distribution. It separates Image Builder from CodeBuild's user-defined source-build commands, ECR's container-image storage and access boundary, and the runtime deployment controller. The lesson connects image identity and tests to security, launch behavior, cost, cleanup and account-appropriate estimated-run and credit-reserve guardrails.

The [six design-only cases](../../examples/image-builder-pipeline/README.md) and [separate assessor notes](../../examples/image-builder-pipeline/ASSESSOR.md) ask learners to select the right tool, fix build inputs, distinguish validation from post-capture tests, hold distribution after a failure, trace exact image identity across Regions, assess cross-account/key requirements, and plan bounded cleanup after a failed run. Organization-dependent sharing stays design-only.

AWS documentation confirms that Image Builder recipes reference base images and components; its pipelines run build, validate, test and distribution workflows; and configured tests must succeed before distribution. Its pricing guidance states no direct Image Builder creation fee but lists supporting costs such as build instances, logs, Inspector validation, EBS snapshots, ECR storage and image transfer. See [Image Builder overview and pricing](https://docs.aws.amazon.com/imagebuilder/latest/userguide/what-is-image-builder.html), [CodeBuild overview](https://docs.aws.amazon.com/codebuild/latest/userguide/welcome.html), and [ECR image publishing](https://docs.aws.amazon.com/AmazonECR/latest/userguide/image-push.html).

Coverage is partial and design-only. No Image Builder component was authored or validated, no AMI/container image was built, no account/Region distribution was checked, and no cost or cleanup was measured. A practical assessment still needs an approved base image and component set, scoped build identity/network, live first-boot/runtime evidence, destination/permission proof, a cost estimate and verified cleanup. The current AWS session remains expired; no live account state was inspected. Independent technical and learner review remain pending.
