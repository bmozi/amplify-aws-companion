# SOA-C03 task 1.2 issue diagnosis and remediation skill review

Internal editorial review, October 19, 2026, against the current [official CloudOps task 1.2 guide](https://docs.aws.amazon.com/aws-certification/latest/sysops-administrator-associate-03/sysops-administrator-associate-03-domain1.html#sysops-administrator-associate-03-domain1-task2). All three skill points have **partial** authored evidence. The [Unit 08 illustrated lesson](../../reader/BOOK-LOCATORS.md#book-000bf1124eccce79), [diagram](../../book/figures/alarm-to-runbook-boundaries.svg), [source and six-case packet](../../examples/alarm-diagnostic-runbook/README.md), [assessor](../../examples/alarm-diagnostic-runbook/ASSESSOR.md) and tested local classifier support these links. JSON parsing is not AWS service validation; no event, target, role or runbook was deployed.

| Official skill | Authored and locally checked evidence | Still needed |
| --- | --- | --- |
| 1.2.1 Analyze metrics and automate remediation strategies | Chapter separates alarm history, EventBridge delivery metrics, runbook execution, fresh alarm read and customer outcome. The packet uses CloudWatch, EventBridge and Systems Manager concepts; it deliberately stops at read-only diagnosis before any automated repair. | Selected service metrics and a reviewed remediation policy with exact scope, permission, approval, stop, rollback and customer proof; compare current Lambda/CloudTrail/AI-assistant options where relevant; live measurement and learner review. |
| 1.2.2 Route, enrich and deliver events; troubleshoot rules | Exact fictional EventBridge pattern, event and target-input JSON plus six changed cases. Local tests reject wrong account, Region, alarm, new state or missing detail, and separate absent match, invocation, target delivery and DLQ states. No EventBridge transformer is implemented. | AWS `TestEventPattern`, target/role/DLQ setup, actual event receipt and metric/log inspection, selected enrichment, retries and replay; independent learner review. |
| 1.2.3 Create or run a custom/predefined Automation runbook | Custom Automation JSON has one read-only `aws:executeAwsApi` `DescribeAlarms` step with declared parameters and outputs. Source is JSON-parsed; local drill tests evidence boundaries. | AWS document validation and versioned creation, execution with scoped separate roles and approved parameters, step/history/permission/cost evidence; compare suitable predefined runbook, and test any future repair with an explicit authorization boundary. |

The current source covers a single fictional account/Region and one metric alarm. It does not establish complete task coverage or production-grade remediation. No live AWS, customer data, price, credit or learner result was observed.
