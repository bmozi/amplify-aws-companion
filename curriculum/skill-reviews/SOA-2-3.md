# SOA-C03 task 2.3 backup and restore skill review

Internal editorial review, updated October 21, 2026, against the [official CloudOps Domain 2 task 2.3](https://docs.aws.amazon.com/aws-certification/latest/sysops-administrator-associate-03/sysops-administrator-associate-03-domain2.html#sysops-administrator-associate-03-domain2-task3). All four numbered skills have individual **partial** links to [Unit 07](../../reader/BOOK-LOCATORS.md#book-a960683877798a14), [the diagram](../../book/figures/integrated-restore-evidence.svg), [seven changed cases](../../examples/integrated-restore/README.md), [assessor reasoning](../../examples/integrated-restore/ASSESSOR.md), [six decision-model tests](../../examples/integrated-restore/test_lab.py), [five Moto S3 API tests](../../examples/integrated-restore/test_s3_version_lab.py) and [E14](../EXERCISES.md#e14). No live AWS backup, object read, database restore or disaster-recovery procedure was executed.

| Official skill | Teaching and local assessment evidence | Still required |
| --- | --- | --- |
| 2.3.1 Automate snapshots and backups for selected resources | The lesson distinguishes resource assignment, schedule, retention and joined customer validation. Changed case 5 asks why a database-only schedule omits the photo. Earlier backup-policy and lifecycle exercises cover additional supported-resource choices. | Scoped AWS Backup plan and actual selected resource assignments; successful and failed jobs, recovery points, retention, access, full current cost and independent learner review. |
| 2.3.2 Restore databases using RTO/RPO and cost | Three fictional database points force rejection of an older missing booking and newer corruption. RDS documentation confirms a point-in-time restore creates a new instance. Earlier local SQLite drills teach separate restoration and reconciliation. | Selected DB service and valid latest restorable time, actual restore/reconnect, complete incident-to-accepted-service timing, measured data loss and cost, independent learner review. |
| 2.3.3 Implement storage versioning | The lesson and local tests distinguish `v1`, wrong `v2`, and a current delete marker and check exact bytes against an independent digest. A Moto S3 API fixture enables versioning, overwrites and marks an object, lists exact versions, reads the confirmed old version, denies an unrelated shop in the application guard, and stages a separate candidate without changing the original or neighboring shop. The [cost bridge](../../examples/storage-cost/versioned-read-path/README.md#connect-the-recovery-inventory-to-the-cost-worksheet) carries emulated version sizes into an assumption-labeled dated public-price subtotal. | Actual selected bucket/version settings, effective IAM/bucket/KMS denial and retained-version read, permanent-deletion and lifecycle controls, whole-run account cost; FSx versioning/snapshot choice where relevant; independent learner review. Moto does not prove live IAM, AWS timing or billing. |
| 2.3.4 Follow disaster-recovery procedures | Case 6 compares backup-and-restore, pilot light, warm standby and active/active through the whole workload, not the database alone. The local gate refuses duplicate dispatch. | Tested selected strategy, identity/keys/routing/capacity/external-effect procedure, safe fault and measured RTO/RPO, full cost and independent learner review. |

The fictional confirmation is supplied and complete. Missing it forces a hold; neither local program can discover truth from damaged copies. The original model checks a decision without service calls; the extension uses boto3 against Moto in memory and does not contact AWS.
