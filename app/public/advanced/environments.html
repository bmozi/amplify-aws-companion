Build a practice room beside the working app

Create a separately identified sandbox, prove its data isolation, and remove it.

Advanced courseFoundation lessonHands-on lab
Your outcome

Create a separately identified sandbox, prove its data isolation, and remove it.

Suggested time: 45–70 minutes. Optional cloud exercise; creates a separate billable backend.

You would not practice knocking down a wall in a room someone is using. A cloud environment is a named collection of services you can change together. A separate frontend address does not automatically mean separate data. The addresses in amplify_outputs.json determine which backend the browser actually uses.

A Gen 2 cloud sandbox creates real AWS resources. It is not an offline simulation. Our helper makes a separate local copy first so sandbox-generated configuration cannot silently replace the live app's configuration.

Prepare without deploying

python3 scripts/prepare-practice.py
npm ci --prefix practice/advanced

The copy deliberately excludes dependencies, build output, generated backend addresses, and environment files. It refuses to overwrite an existing practice folder. Review your identity from Lesson 8 and use invented records.

Create the practice backend

python3 scripts/ampx-session.py --app-dir practice/advanced   sandbox --identifier advanced --once
npm run dev --prefix practice/advanced

The first command makes one billable backend deployment and exits. It uses the owner project's account guard and refreshable sign-in; review and adapt both before another account uses it. Do not run it when the current identity, whole-run estimate, spending limit, reserve or cleanup check is missing. The second command serves the page on the local address printed by Vite. Sign up in this new user pool; your original app account will not automatically exist here.

Prove which room you are in

  1. Compare the user-pool ID, API URL, and storage bucket in the practice and live amplify_outputs.json files. They must differ.
  2. Save “practice only” in the local app. Open the hosted lab. The practice note must not appear there.
  3. Save a different note in the hosted lab. Check that it is absent from practice.
  4. Record the sandbox stack name from CloudFormation and its resource list. A frontend URL alone is insufficient evidence.

Sandbox isolation is convenient for one learner. Separate AWS accounts give stronger administrative and billing boundaries for larger teams, at the cost of more identity and deployment setup. Choose a boundary that matches the damage an experiment could cause.

Stop and remove

Stop Vite with Control-C. Closing the terminal does not delete the backend. Remove the invented files and notes in the practice UI first, then run:

python3 scripts/ampx-session.py --app-dir practice/advanced   sandbox delete --identifier advanced

Read the deletion confirmation and wait for completion. Check CloudFormation, S3, DynamoDB, Cognito, and logs for retained resources from that exact sandbox. Keep any retained resource's name and reason in your evidence. Never delete the shared CDKToolkit stack merely because one sandbox is finished.

The page opens but API calls fail

Check that the practice outputs were generated, that the local app was restarted after configuration changed, and that you signed into the practice user pool. Do not copy the live outputs into practice to make the error disappear; that reconnects the practice page to live services.

Use AI as your engineering partner

Give Codex the relevant source files and sanitized evidence. Ask: “Compare the working app and practice configuration. Find every value that could accidentally target the wrong environment. Do not deploy or expand permissions.”

Verify: Check account, Region, resource names and generated outputs before any write. Explain the result in your own words and name one condition that would change it. Set a spending and action boundary before permitting cloud work.

Evidence to collect

  • Compare three backend identifiers between environments.
  • Demonstrate two-way absence of private test notes.
  • Record actual deletion and any retained resources.

Use the source bundle’s examples/advanced/evidence-template.json. Keep credentials and private data out of shared results.
