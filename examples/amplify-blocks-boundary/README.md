# Change the Blocks promise before adding a new backend

This is a cloud-free architecture exercise for the [AWS Blocks preview lesson](../../reader/BOOK-LOCATORS.md#book-6dda7767ab0d34a9). Read the [official Amplify integration overview](https://docs.amplify.aws/react/build-a-backend/aws-blocks/), [scaffold guide](https://docs.amplify.aws/react/build-a-backend/aws-blocks/get-started/) and [runtime explanation](https://docs.amplify.aws/react/build-a-backend/aws-blocks/how-it-works/), then answer before opening the separate [assessor](ASSESSOR.md). The fictional bakery has an existing Amplify Gen 2 backend; our actual repository has **not** installed Blocks. No AWS resource is needed for this packet.

For each case, name (1) what the local observation proves, (2) the required server-side authority check, (3) what changes in the deployed Gen 2 backend, (4) one positive and one denied/failed observation, and (5) the new cost and cleanup inventory. Use **unknown** when a supplied fact cannot answer a question. Do not call a simulated local result an AWS denial.

1. **A green greeting.** A developer scaffolds a Blocks API with `greet(name)` and gets `Hello, Maya!` from a local loopback call. No auth check appears inside the method. Maya wants each customer's private order notes. Can the green greeting authorize private notes? What must the note method do before reading a caller-supplied `orderId`?
2. **A signed-in stranger.** The new `getNote(orderId)` method calls `requireAuth(context)` but reads the supplied ID without checking its owner. Leo signs in and guesses Maya's order ID. What has the token check established? What must the API verify or change in its key design? Specify a direct denied-path test.
3. **One source, two runtimes.** A teammate uses a local KVStore and sees one note after restarting the browser. They say the DynamoDB table exists in the AWS account. Separate the local memory/filesystem path from the deployed `ampx` path. Which file advertises the Blocks API URL after deployment, and why is that URL not a secret?
4. **Only the website shipped.** The existing manual GitHub publisher uploads a static ZIP and reports a current hosted source marker. The teammate has added a Blocks definition to a branch but never deployed the Gen 2 backend. May the team claim the Blocks API is live? Name the missing owner, deployment action and customer-path observation. Explain which publication switch stops only new frontend jobs.
5. **The dollar-one shortcut.** The team copies the managed Hosting storage/transfer subtotal into its Blocks proposal. It omits the nested stack's API, Lambda, KVStore table, logs, IAM review and retained resources. The current account balance and credit applicability have not been read. Explain why a live run cannot yet be approved. What must be priced, bounded and later inspected before a claim about cost or cleanup? Choose spending and credit-reserve limits for the account in use.

Ask Codex for an alternate answer to case 2 and case 5. Have it identify the exact method, caller, resource owner, first AWS write and missing receipt. Keep the first unaided response; a corrected AI-assisted answer is a different learning observation.

At the October 21, 2026 research checkpoint, an **isolated temporary** backend-only scaffold from `@aws-blocks/create-blocks-app@0.3.0` installed outside this repository. Its typecheck passed, and its public `greet` returned `Hello, Maya!` from a loopback JSON-RPC call with telemetry disabled. The scaffold's installer reported 31 advisory-affected package entries (30 high, one low). No Blocks package, lockfile or backend change was copied into this repository. This observation supports only the local public-method example. It does not prove a private method, the Amplify integration, generated AWS permissions, current package safety or cloud behavior. Review the current version and advisories before adopting the preview toolkit.
