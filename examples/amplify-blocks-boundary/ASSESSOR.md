# Assessor: Blocks is another backend path, not an authorization result

Keep this file out of the learner's first attempt. These are reasoning criteria for fictional cases, not independent learner outcomes or a verified AWS deployment.

1. The local greeting proves a public method responded on one loopback process. The scaffolded method has no auth call; a typed client cannot make it private. A protected note method calls `requireAuth(context)` and then binds access to the verified `sub` or checks the exact order's membership before reading. A test needs an unsigned request and an unrelated signed-in user, not merely a hidden UI control.
2. `requireAuth` establishes a valid signed-in token for the configured pool and client; it does not authorize any arbitrary `orderId`. The server must derive a per-user key or verify order membership using trusted data. Leo's direct API request for Maya's order must be refused or return no accessible note; Maya's own direct request must work. Also inspect list/update/delete paths if provided. A local denial would not prove AWS enforcement.
3. AWS documents local memory/filesystem implementations selected separately from CDK synthesis and AWS runtime. A browser restart could leave a local server and file alive; that says nothing about a deployed table. The Amplify integration creates a nested CDK stack and surfaces `custom.blocks_api_url` in `amplify_outputs.json` after deployment. An endpoint address is public configuration; backend token checks and data authorization remain necessary.
4. The checked-in GitHub publisher is a frontend-only manual artifact route. It does not call `ampx` or deploy the new nested backend stack. The team needs a reviewed Gen 2 backend change through its own owner and scoped identity, then actual API/denial and visitor checks. `AMPLIFY_PUBLISH_ENABLED=false` stops new jobs of that one workflow; it is not an IAM deny and does not delete any existing website or backend.
5. The copied managed Hosting subtotal omits a different infrastructure path. Inventory API Gateway/API endpoint, Lambda, selected KVStore/DynamoDB resources, logs, deployment support and retained state, plus existing Hosting/backend use and test traffic. Review current rates, Free-plan/credit eligibility, run duration, resource counts, cleanup and later billing with the actual account. An unknown balance, missing cost rows or unclear cleanup fails the live-run decision. A budget alert is not a hard cap. The preview status and dated scaffold audit are additional reasons to review before adoption, not proof that the concept cannot be taught locally.

Score the first attempt on five independent dimensions: path separation, backend authorization, infrastructure ownership, whole-run cost, and evidence limits. A correct sounding service name without an access test or cost boundary earns at most a plausible answer. Do not average a public private-note method or an unbounded live run into a passing result.
