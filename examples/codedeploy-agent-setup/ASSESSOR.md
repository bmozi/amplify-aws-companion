# Assessor notes: put the CodeDeploy agent on the right machine

These notes explain a good diagnostic order. They do not prescribe one universal configuration. AWS support, minimum agent version, package path and required permissions vary by operating system, architecture, deployment mode, source and Region. Recheck the current primary documentation before implementation.

1. **Online but absent:** Systems Manager online indicates its own managed-node channel, not that the CodeDeploy deployment group selects the instance or its CodeDeploy agent is supported, current and communicating. Compare the exact deployment group key/value or Auto Scaling membership, current instance identity and Region, supported OS/architecture, agent process/version and agent log. If the instance is selected but not healthy, check the actual deployment event and control-plane communication before editing the tag or permission.
2. **Waits forever:** AWS documents outbound HTTPS over port 443 for the CodeDeploy agent. Opening inbound SSH does not repair a blocked outbound connection. Check DNS, route, security-group/NACL egress, required regional CodeDeploy endpoints and the selected artifact source; if Systems Manager is the installer/updater, include its managed-node endpoints and role path. A private endpoint, controlled NAT or other approved egress design must fit the selected service endpoints and cost. Do not claim that “port 443 open” proves DNS, TLS, destination policy or artifact authorization.
3. **Swapped roles:** The EC2 instance profile is attached to the host and grants the agent access to the application revision source, such as the intended S3 bucket. The CodeDeploy service role is assumed by the service to identify/manage instances and, for the deployment type, interact with Auto Scaling, load balancing, alarms and other required resources. The role names and AWS managed policies are examples; review exact action/resource scope. Never attach a service-wide deployment role to every instance as a shortcut.
4. **Wrong platform:** The CodeDeploy agent is required for EC2/On-Premises CodeDeploy deployments and not required for ECS or Lambda. ECS investigations follow the task set, service, target groups, container/application health and deployment events. Lambda investigations follow function versions/aliases, traffic routing, permissions and deployment events. The platform owns the right health evidence.
5. **Golden image:** Both approaches need an explicit tested version and a controlled rollout. Baking a pinned version improves startup repeatability but can age; Systems Manager can install/update at scale but requires healthy Systems Manager connectivity, authorization and package selection. Use staged rollout, verify the observed version and service health, keep a prior known-good image/package route and record differences. AWS's current guide states a minimum supported CodeDeploy agent version and notes version 2.x regional rollout/version requirements; verify exact current facts before choosing a pin.
6. **First broken link:** Determine deployment target membership and selected Region; inspect agent service/process/version; inspect agent log and outbound CodeDeploy endpoint path; establish the actual principal and artifact-source permission, including any KMS key path if encrypted; confirm revision download and disk-space/unpack state; only then inspect lifecycle hook output, exit code and application health. Use the specific deployment and instance logs, not a generic “failed” label. Do not widen permissions until the request, target ARN and denial source are known.

Useful official references: [agent support, version, communication and configuration](https://docs.aws.amazon.com/codedeploy/latest/userguide/codedeploy-agent.html); [Systems Manager install/update procedure](https://docs.aws.amazon.com/codedeploy/latest/userguide/codedeploy-agent-operations-install-ssm.html); [EC2 instance profile purpose](https://docs.aws.amazon.com/codedeploy/latest/userguide/getting-started-create-iam-instance-profile.html); [service role purpose](https://docs.aws.amazon.com/codedeploy/latest/userguide/getting-started-create-service-role.html); and [EC2 troubleshooting](https://docs.aws.amazon.com/codedeploy/latest/userguide/troubleshooting-ec2-instances.html).

A sound answer does not conflate instance reachability with CodeDeploy readiness, an agent with the service role, package access with deployment authorization, or deployment success with healthy business behavior. It identifies each stage and the evidence needed before a change. The worksheet changes no account settings.
