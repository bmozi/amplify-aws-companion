# Put the CodeDeploy agent on the right machine

This design-only exercise supports DOP-C02 task 1.4 skill 02: configure deployment agents. Read [the delivery lesson](../../reader/BOOK-LOCATORS.md#book-9eeb130e97d97c79), draw the identity and network paths, and answer each case before reading the separate [assessor notes](ASSESSOR.md). No AWS commands or machine changes are part of this worksheet.

For each case, record: compute platform, operating system/architecture, agent requirement and version, installation/update owner, instance profile, CodeDeploy service role, artifact location, network path, target-group selection, local lifecycle hooks, useful logs, safe test and rollback/cleanup owner. Separate **installed**, **running**, **connected**, **authorized to fetch**, **hook succeeded**, and **application healthy**; these are different observations.

## Cases

1. **Online, but absent from the deployment.** A Linux EC2 instance is visible as online in Systems Manager, but CodeDeploy reports no healthy targets for the intended deployment group. The instance has a tag that looks like the expected group label. Decide what to verify about exact tag key/value, group selection, CodeDeploy agent installation/status/version, target operating system support and Region. Explain why Systems Manager being online proves neither CodeDeploy readiness nor artifact access.
2. **The release waits forever.** A private-subnet EC2 target has the agent installed and a current-looking service status. It cannot reach public endpoints and has no NAT path. A teammate proposes opening inbound SSH from the internet. Trace the agent's actual communication direction and port. List the CodeDeploy, artifact-source and Systems Manager paths this chosen installation method needs, then identify a safe network design check.
3. **Two badges were swapped.** Someone attached `AWSCodeDeployRole` to each EC2 instance and gave the CodeDeploy service an instance profile. The agent starts but cannot fetch the S3 revision, and the deployment service cannot expand the intended Auto Scaling group. Identify which role is intended for the service and which for the EC2 host. State what each should be able to do and which current service documentation should define exact permissions.
4. **The wrong platform received an agent.** The same deployment diagram shows ECS tasks, Lambda functions and EC2 instances. A configuration script installs the CodeDeploy agent on “every deployment target.” Correct the platform boundary. Identify where you would investigate deployment health for ECS and Lambda instead of searching for a host agent.
5. **A golden image, old agent.** A tested AMI was built months ago. New instances launch with an older agent than the current minimum required by CodeDeploy. Compare pinning a known-tested agent version in the image with installing/updating it through Systems Manager. Name version, OS, architecture, rollout-ring, drift and rollback evidence. Explain why “latest” without a recorded version can make two otherwise identical servers behave differently.
6. **Find the first broken link.** The deployment fails before the first lifecycle hook. The only evidence is “instance failed.” Order read-only checks for target selection, agent process, agent/control-plane connectivity, artifact read permission, revision download and local disk/log state. State which findings would move diagnosis to hook scripts or application health.

If any case motivates cloud practice later, design one disposable instance only after confirming an approved AMI/size, the current agent version and OS support, scoped non-root identity, role separation, subnet egress, artifact permissions, alarms/stop condition, and a complete cost estimate within spending and reserve limits chosen for the account. Define cleanup for the instance, volume, image, logs and revision. Do not create an instance merely to answer the worksheet; organization-based targets remain design-only.

Ask Codex to challenge your diagram: “Trace the caller, CodeDeploy service role, EC2 instance profile, agent, artifact source and network direction. Which observation distinguishes each failure stage? Cite current AWS documentation. Do not run commands or change resources.” Preserve your first diagnosis and record any claim that a local or conceptual review cannot verify.

These are original practice cases, not calibrated exam questions. No agent, IAM role, deployment group, learner result or live AWS behavior was tested.
