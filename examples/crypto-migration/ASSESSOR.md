# Assessor notes: cryptographic migration

Use after writing your own response. Several priorities can be defensible; assess the evidence and reasoning rather than matching wording.

1. The inventory separates worker-to-KMS transport, the office path, the recovery utility, stored-data protection and software-signature verification. It names missing versions, owners and participant compatibility. Long confidentiality needs motivate investigation; they do not prove a current exploit or a legal deadline.
2. The matched worker event supports the stated hybrid negotiation for that observed request, and the result supports that operation's functional success. It does not cover every request, other environments, signatures or stored ciphertext. Record observation time and identity rather than extrapolating account-wide.
3. Missing `tlsDetails` on the service-mediated call is an explicitly documented visibility limitation. It proves neither classical nor hybrid negotiation. Seek an applicable supported observation or retain the uncertainty.
4. The office failure needs diagnosis: exact client and intermediary versions/configuration, failure stage and safe controlled comparison. A larger handshake or unsupported group is a possibility from AWS guidance, not an observed cause here. No request should disable trust or hostname verification as a repair.
5. The old device verifies a signature, a separate function from TLS key exchange. Establish supported algorithms, update ability and lifetime before choosing a migration. A server-side upgrade alone cannot establish verifier compatibility.
6. Key rotation, transport negotiation and signature migration are different changes. New transport evidence does not rewrite old stored data; rotating a storage key does not establish the required connection or signature behavior.
7. A useful rollout plan bounds participants and paths, requires functional and security evidence together, compares performance against an agreed baseline, includes recovery tools and defines a stop owner. An exception has scope and expiry. Restoring the previous configuration may restore service while preserving an earlier risk; both belong in the record.

A good answer can postpone rollout while completing discovery. It must not invent live measurements, universal thresholds or approvals. This exercise does not test cryptographic implementation or AWS behavior.
