# Assessor: four-record audit path

A strong answer separates **recorded API activity**, **optional model content**, **instrumented agent steps** and **application disposition**. The baseline includes all four routes, yet its business status is `human_review_required`; no customer success follows from a model response. Its stream-completion event is an additional service event, not a second API call. The model log's synthetic marker remains a sensitive-content warning despite `response_masked: true`.

For the changed cases: disabled invocation logging makes content collection not expected from this configuration; an enabled route with a missing matching record is unknown; a wrong account/Region is not the same case; `bedrock-mantle` is outside the invocation logging route described by the cited Bedrock page, and the unchanged runtime CloudTrail record does not prove a new Mantle call; a missing receipt leaves the business outcome unknown. A trace cannot manufacture a receipt. The fixture does not evaluate log delivery delay, schema evolution, integrity, authenticity, or end-to-end AWS behavior.

Require the learner's paper design to name its selected account, Region, endpoint, operation/event category, principal, correlation key, collection scope, destination, retention/deletion owner, sensitive-data controls, retrieval test, late/missing-record interpretation and business disposition. A proposal that enables broad content or data-event collection without a current estimate and purpose needs revision. A proposal that treats these local tests as live AWS proof also needs revision.
