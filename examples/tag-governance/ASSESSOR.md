# Assessor: tag controls have different reach

1. **Wrong value:** Enforced basic tag-policy rules can reject a supported request bearing a noncompliant `CostCenter` value or spelling. The learner must name the supported resource/action scope and seek an actual denied create plus absence of the resource, not infer enforcement from a policy document.
2. **Missing key:** Basic tag-policy enforcement does not stop an untagged create. A properly enabled required-key IaC validator may warn or fail a covered deployment. A carefully scoped SCP may deny a supported member-account create request lacking the requested tag; its condition semantics and action support need real validation. Neither one proves that every creation path uses that IaC tool or member-account role.
3. **No tag-on-create field:** A universal missing-tag deny can make creation impossible. Check the current service API, identify a narrow exception principal/time window or approved alternate path, attach tags promptly when supported, and reconcile the real resource. If the requirement cannot be met, escalate the design choice; do not silently exempt an entire service or invent tag support.
4. **Untag and bypass:** A create guard is not an untag guard. Protect supported tag-mutation actions separately and inventory existing resources. SCPs do not restrict principals in the Organizations management account or service-linked roles. An IaC check does not see resources created outside its covered workflow. A Config rule or other supported inventory may detect missing tags after the fact.
5. **Stale finding:** Re-read the exact account, Region, resource ID, current tags and evaluation time. Review the proposed mutation's target set and exception owner. A broad automation could alter a held or production resource unrelated to the original finding; a Config finding is a trigger for review, not authorization to edit every matching object.

A strong answer supplies the supported-action matrix and a staged test plan for **allow, deny, detect, exception and rollback**. The matrix remains a design until official resource/action support and organization-level observations are checked. No AWS policy or Config rule has been deployed here; no customer tag state, bill allocation, or learner performance has been verified.
