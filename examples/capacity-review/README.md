# Capacity and quota review: ten changed cases

Design-only exercise. No AWS account, credentials, quota increase or deployment is needed. Read [unit 22](../../reader/BOOK-LOCATORS.md#book-98530e7b95042c56), then answer these prompts before opening the assessor notes. All numeric limits below are fictional, not AWS defaults.

1. **Replacement overlap.** Limit 20 units; old deployment 12, replacement 12, unrelated work four. Show normal, overlap and final demand. Compare a quota increase with staged replacement while preserving a required minimum of ten serving units. State what more you need to know about replacement increments and readiness.
2. **Different units.** A machine requires four capacity units. Eight units remain available under the relevant quota. An operator proposes launching eight machines. Explain the mistake and the theoretical maximum before other constraints.
3. **Wrong remedy.** A launch returns `InsufficientInstanceCapacity`, while the relevant quota and usage were checked and leave headroom. A teammate proposes requesting a larger quota. Identify the missing evidence and propose a bounded alternative investigation.
4. **Recovery mismatch.** The normal Region has a 40-unit applied quota. A recovery record shows only a published default of 20 in the other Region. The recovery workload needs 24, plus six for replay. Identify which claims are established and which remain unknown.
5. **Check-then-change race.** A preflight finds eight unused units. Two independent deployments each need six and proceed from that observation. Explain why both checks can pass while both deployments cannot fit together. Predict and run the [local conditional-record exercise](../quota-race/README.md), then name an operational coordination option and its limitations.
6. **Permission and single-item limits.** A caller receives an authorization denial. Separately, one request exceeds a documented payload maximum. Explain why raising a resource-count quota is not the remedy for either observation. State the evidence needed to choose the correct change.

7. **Duration growth.** A Lambda event function receives 40 requests/second with mean duration 0.5 seconds. The mean grows to two seconds while arrivals remain steady. Estimate average concurrency before and after. Its fictional reserved concurrency is 30. Explain why spare account capacity does not remove that function ceiling and why the averages do not prove burst safety.
8. **Wrong kind of preparation.** The function spends most of its time waiting on a database query. A teammate proposes provisioned concurrency to make the database faster. Explain what initialization changes and what still needs measurement. Compare reducing query work with adding prepared environments.
9. **Target mismatch.** Provisioned concurrency is configured for an alias pointing to a published version, but a caller invokes the unqualified function. A teammate expects every call to use the prepared allocation. Identify the invocation-target check and explain why a provisioned allocation is neither a universal latency guarantee nor a hard spending cap.
10. **Protect the dependency.** In a fictional model, each in-flight invocation holds exactly one database connection. The database can safely support 50 simultaneous connections for this workload, including ten used by other clients. An operator wants to raise function concurrency to 80. Compute the simple remaining allowance, then name three real behaviors that would invalidate the one-connection-per-invocation model. Compare a function ceiling, dependency optimization and a reviewed database capacity change; include customer impact and cost.

For each case submit: units and scope, arithmetic when relevant, evidence versus assumptions, two plausible options, effects on availability/cost, and a stop condition. Use a fictional account identifier if drawing a target record. Do not invent approval, provisioning or successful recovery evidence.

Ask Codex to play the reviewer after your first answer. Keep its suggested changes separate from your unaided reasoning. This is not an official exam question set or a scored learner result.
