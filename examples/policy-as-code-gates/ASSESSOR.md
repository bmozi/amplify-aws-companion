# Assessor: policy-as-code placement

1. **Pull request:** A local/CI validator can reject the reviewed template file and report a specific property failure. It cannot prove an unreviewed repository, future manual change or deployed resource is compliant.
2. **CloudFormation path:** An appropriately configured Hook can evaluate selected CloudFormation resource operations regardless of the originating repository. `WARN` records without blocking; `FAIL` can prevent the targeted operation. Verify activation, target operations, filters, permissions and actual fail result. [AWS Hook concepts](https://docs.aws.amazon.com/cloudformation-cli/latest/hooks-userguide/hooks-concepts.html).
3. **Direct path:** A CDK aspect runs at CDK synthesis; a CloudFormation Hook applies to its configured CloudFormation path. Neither automatically evaluates an unrelated direct API call. IAM/SCP/resource controls may constrain applicable actions but need their own precise request semantics and negative tests; a Config rule may detect a later noncompliant state under its recording/evaluation scope.
4. **Drift:** A template check is proactive for that input. CloudFormation drift detection compares supported properties with a stack's expected state; AWS Config observes/evaluates selected recorded resources and rules. Neither should trigger blind overwrite of an emergency change. Review owner, freshness, business effect, desired-state owner and rollback. [AWS drift detection](https://docs.aws.amazon.com/AWSCloudFormation/latest/UserGuide/using-cfn-stack-drift.html).
5. **False pass:** The tiny Python gate checks presence of `BucketEncryption` and four boolean flags in a JSON object. It does not parse all CloudFormation semantics, resolve dynamic values, test effective resource settings or inspect other resource types. Test the actual rule with valid and invalid templates, schema validation, change-set review and authorized deployed allow/deny observations. [AWS Guard validation](https://docs.aws.amazon.com/AWSCloudFormation/latest/UserGuide/cloudformation-guard.html).
6. **Organization:** Start with a narrowly scoped canary and explicit recovery authority. An SCP applies to member-account principals under its hierarchy, not the management account; it does not grant permissions. Organization-level changes remain design-only in this exercise.

The lab makes enforcement location and bypass paths visible. It does not satisfy the official skill's full implementation, proactive AWS enforcement or drift remediation requirement. A passing local gate is only local fixture evidence.
