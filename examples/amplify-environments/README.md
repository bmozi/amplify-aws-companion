# Which Amplify environment did the visitor actually reach?

Maya sees a local bakery page, a practice branch and a preview URL. Those are three **frontend locations**. They do not tell her which cloud backend receives an order. Read the [illustrated environment lesson](../../reader/BOOK-LOCATORS.md#book-1b66ea0493099d51) and write your answers before opening the [assessor reasoning](ASSESSOR.md). This is an original, cloud-free design exercise; the cases are fictional and no command below deploys AWS resources.

For each case, draw two arrows: **where the page is served** and **where its Auth/Data/Storage calls go**. Then record (1) the command's effect, (2) the resource owner, (3) a positive and a denied or failure-path observation, (4) continuing cost meters, and (5) the off switch plus evidence that it worked.

1. **A local page, a real order.** Maya runs a local dev server. Its `amplify_outputs.json` came from a personal cloud sandbox. A teammate says, “No AWS call is possible because the page is on localhost.” Identify what the local URL proves, what the outputs can route, and which cloud inventory would settle the matter.
2. **The address-book shortcut.** Maya edits a backend rule in source, then runs `ampx generate outputs` for the existing practice branch. The command succeeds. She claims the branch now enforces the new rule. Name the missing operation and an API-level denial check that would matter after a real deployment.
3. **A new back room behind an old page.** A scoped CI run completes `ampx pipeline-deploy` for the practice branch, but the separately published static frontend is still the prior ZIP. Can customers be promised the new screen or behavior? Explain the possible backend/frontend mismatch and the evidence needed from both paths.
4. **Two URLs, one set of test orders.** A preview frontend has its own URL but its build generates outputs for the `dev` backend. A tester creates a booking. Explain where the record may land and whether the preview is an isolated data environment. Change the design so the preview has separate data, and name the added resource, cost and cleanup work.
5. **The watcher is quiet.** Maya presses Ctrl+C after using `ampx sandbox` and closes her laptop. No terminal process remains. A bill later includes storage and API requests. Which claim did Ctrl+C establish? What separate action and readback would support a sandbox removal claim? Include the possibility of retained resources and delayed billing.
6. **A “small” sandbox schema change.** The team proposes changing a DynamoDB index and a required Cognito attribute while preserving a hand-entered test customer. Decide what data-lifecycle risk must be reviewed before the edit. Why is a passing TypeScript check insufficient? Give a safer test-data and recovery plan before any cloud run.

Run the [synthetic destination checker](../environment-boundary/README.md) for an executable continuation of case 4. Its invented outputs compare browser destinations against a separately supplied plan. It cannot prove AWS deployment, authentic identity or actual data isolation.

Ask Codex to fill the two-arrow record for case 3 and challenge it with case 4. Require a citation to the exact backend command and the actual frontend publication evidence; do not accept “Amplify succeeded” as one combined receipt. These cases remain paper work until a scoped non-root identity, current account-plan and credit check, whole-run estimate against chosen spending and reserve limits, and cleanup plan are reviewed. A design packet does not reserve credits or authorize an organization-wide sandbox.
