# Assessor reasoning: environment and output boundaries

This is an author key for the [six cases](README.md), not a measured learner result or a claim that this account ran Amplify. Credit an answer only when it separates frontend location, backend destination and the evidence for each.

1. **Local page:** localhost establishes where browser files were served. The sandbox-generated outputs can point the client at Auth, Data and Storage resources in AWS. Inspect the selected account/Region, sandbox stack and generated outputs before calling the path local-only. A local page load is a positive frontend observation; an unrelated-user API denial is separate backend evidence. Cloud service and log meters can continue while resources remain.
2. **Read versus deploy:** `ampx generate outputs` retrieves connection configuration for an existing environment. It does not apply Maya's edited backend rule. A separately reviewed backend deployment must precede a current rule claim. Test an allowed request and an unrelated actor's denied API request against the intended branch after deployment; a schema compile or regenerated address book is too narrow.
3. **Backend versus frontend:** `pipeline-deploy` can update branch cloud resources without publishing this lab's static ZIP. An old browser might call a changed API with stale assumptions, or the new source UI might simply be absent. Verify the backend deployment receipt, generated configuration, exact published ZIP/marker and a customer-path result. Backend success alone supports no claim that the new screen was served.
4. **Shared preview:** generating `dev` outputs makes the preview's browser call the `dev` resources, subject to their permissions. Its URL is separate; its users and records may be shared. A truly separate preview backend needs a distinct deployment and outputs, plus per-preview Auth/Data/Storage/logging estimates, user/data isolation tests and explicit teardown. Sharing can be an intentional lower-resource choice if testers accept the shared-data boundary.
5. **Stopping versus deleting:** Ctrl+C stops the local watching session. Depending on the chosen prompt/action, it is not sufficient evidence that the cloud stack disappeared. Use the documented sandbox delete route for the exact environment, inventory its CloudFormation and dependent resources afterward, and reconcile later charges. Removing an outputs file or closing a terminal is not cloud cleanup.
6. **Schema change:** AWS documents sandbox DynamoDB GSI and unsupported Cognito user-pool changes that can recreate resources. A compile proves source shape, not preservation of a hand-entered record or account. Use disposable synthetic data, record what may be destroyed, preserve any required test fixture outside the sandbox, and define a verified restore or reseed path before editing. Do not experiment on a production-like user pool to learn this behavior.

A strong response also names a current scoped identity, exact Region and resource inventory, priced verification and cleanup, and spending and reserve limits chosen for the account. None of these paper answers establishes current AWS state, a successful sandbox deletion or customer behavior.
