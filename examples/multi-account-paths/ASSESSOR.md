# Multi-account paths: assessor reasoning

These are authored criteria for fictional cases. They are not an IAM policy simulation, AWS integration result or actual account inventory.

1. An account boundary should answer an ownership, environment, audit or incident need. One account can be reasonable for a tiny experiment if scoped roles and cleanup are sufficient. Separating experiment and production reduces a shared administrative failure boundary but adds cross-account deployment and access. Network/operations/log accounts can clarify ownership and evidence custody when the organization can operate them; they also add service integrations, budgets, routing, recovery and retirement work. A bigger account tree without those requirements is not automatically safer.
2. RAM sharing of a supported subnet lets eligible participants use that resource within its documented scope; it does not grant general administrator access to the owner account. Check organization-sharing enablement, share/permission, Region, consumer IAM, network-owner route and security decisions, quotas, target placement, service reachability and an unauthorized network-edit denial. An OU change can change the participant set. Inspect actual share membership and workload dependency before moving it. [RAM sharing](https://docs.aws.amazon.com/ram/latest/userguide/getting-started-sharing.html), [shared-subnet behavior](https://docs.aws.amazon.com/vpc/latest/userguide/vpc-sharing-share-subnet-working-with.html).
3. The receiving bus permission only admits eligible events. Sender rule/role, bus acceptance, receiver account-scoped match, target permission, retry/DLQ and recipient delivery each need separate observation. The rule that lacks an account filter deserves review because a matching event from another admitted account could trigger it. A near-match from a different account or unrelated event type should be rejected by the intended rule. A failed target needs an observable failure metric and, where appropriate, DLQ with access/retention/redrive owner. The page itself is not deployment success or customer-impact evidence. [Cross-account bus rules](https://docs.aws.amazon.com/eventbridge/latest/userguide/eb-cross-account.html), [rule DLQ](https://docs.aws.amazon.com/eventbridge/latest/userguide/eb-rule-dlq.html).
4. A management-event trail does not prove the selected S3 object read was logged. Review whether the relevant data-event resource and Region are selected, delivery is permitted, encryption/key access and storage/retention are correct, and an authorized investigator can retrieve a specific matching event. Count additional data-event, storage and query costs. A later configuration change cannot manufacture an omitted past record. EventBridge notification and CloudTrail audit coverage are different channels. [Organization trail event selection](https://docs.aws.amazon.com/awscloudtrail/latest/userguide/creating-an-organizational-trail-in-the-console.html).
5. Repeat the matrix by account and Region: RAM resource type/share/consumer/access/network result; sender rule/role, receiver bus/rule/target, failure destination and actual operator notice; trail selectors, destination delivery and authorized read. Verify Region eligibility and full-path pricing before a live proposal. A known-good booking and intentional denial provide stronger application evidence than a share or rule status. Local fictional guards establish none of these service results.
6. Identify every consumer and retained obligation before changing membership or share scope. A stopped share may block new use while existing participant resources or retained data require separate treatment under the selected service. Preserve needed logs and decryption/reader authority, move alert ownership, settle shared resource and storage cost, test the alternate network/recovery path, then let named owners approve the transition. Record the point where a failed step stops the exit and how to restore service without widening access indefinitely.

Look for three independent contracts: resource usability, timely selected notification, and durable scoped audit evidence. Each has its own least-privilege path and failure test. This exercise makes no live integration or learner-outcome claim.
