# Study a publisher without turning one on

Imagine a delivery checklist pinned to a wall. Reading it does not start a truck. A GitHub Actions workflow is different when its YAML file lives in `.github/workflows/`: GitHub recognizes that location and can offer its trigger. This directory holds an **inert teaching copy** of the [Amplify publication workflow](amplify-publish.yml). GitHub does not run it from `examples/github-workflows/`.

Read the [caller](amplify-publish.yml) together with its [reusable workflow](reusable-amplify-publish.yml). The caller's `typecheck` job checks source; the reusable workflow's `build` job packages browser files; its separate `publish` job requests an AWS role after its checks. The source requires a manual input, a selected cost scenario and an enabled repository variable. These conditions describe the example, not a live approval or spending cap. The source repository maintains equivalent workflow files separately; this teaching packet need not include them in an active location.

To practice, draw two columns: **what a push alone can start** and **what still needs a person, a variable, a role and a cost review**. Ask Codex to point to the exact lines that support each answer. The caller specifies `workflow_dispatch`, not a push trigger: a push alone does not start this publication workflow. The caller also refers to the reusable workflow by its `.github/workflows/` path. Copying only the caller into that directory would leave that dependency missing unless the reader supplies it separately. Even with both files present, job eligibility and AWS access depend on their conditions and the reader's own GitHub and AWS configuration. Do not activate them merely to follow the exercise. A real deployment needs a separate scoped identity, account plan, whole-run estimate, credit and budget review, customer-path check and cleanup owner.

The [publisher-role lesson](../../reader/PUBLISHER-ROLE-FIELD-LAB.md) walks through those decisions. The [dependency field lesson](../../reader/DEPENDENCY-FIELD-LESSON.md) explains why a passing builder audit or artifact hash is only one part of a release decision. Never place credentials in a workflow file; inspect examples and configure your own destination before any authorized use.
