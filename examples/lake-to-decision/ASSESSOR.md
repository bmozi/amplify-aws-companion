# Assessor reasoning: lake to decision

Read after an independent attempt. These are fictional constraints, not calibrated exam scoring or a deployed data platform.

1. **Raw bucket:** S3 arrival and a catalog row establish storage/discovery, not business acceptance. Preserve source/arrival lineage and original bytes; validate trusted sender, shop scope, ID, units, duplicates, completeness and published version. Test a permitted finance query and denied unrelated query, then separately test direct raw-object access. Lake Formation table rules do not automatically block S3 API access granted elsewhere. A row-total check misses `001` becoming `1`.
2. **Revoked grant:** Revocation can stop a future governed query but cannot recall an already exported file. Name the export owner, storage location, audience, retention, backups and deletion/expiry evidence. Protect query result buckets and chart downloads as new copies. Verify denied future reads and separately reconcile copies already distributed.
3. **NAS move:** Direct copy and DataSync can both be candidates for a supported one-time path. Compare source/network, agent/service, transfer and S3 request/storage, verification, retries, operator work and overlap charges using current prices. An ideal link-speed lower bound is not a schedule promise. Inventory source changes, run a final delta or freeze, verify destination identities/contents and actual application reads before retiring NAS. A successful task report alone is not business cutover.
4. **Continuing supplier:** A managed SFTP endpoint such as AWS Transfer Family addresses ongoing partner protocol and identity; DataSync addresses supported transfer tasks; S3 File Gateway addresses continuing NFS/SMB-style file access with cache/outage considerations. One tool need not serve both supplier and office application. Price persistent endpoints/gateway, transfer, requests, storage, logs and network; verify supported pairs and protocol operations.
5. **Flattering chart:** The promised grain is one accepted sale per shop/day before a separate tag allocation policy. A duplicate and missing row can cancel in a total. Compare complete expected `(shop, sale_id, amount)` rows with the query output; test tagged and untagged rows and canceled-sale policy. Then review chart filters, refresh/version and audience.
6. **Partner aggregate:** Ten purchases from one person fail the stated five-distinct-customer condition. Even five people passing that one condition does not certify privacy or authorization. Compare a static approved export with governed/constrained analysis by freshness, revision, recipient rights, retained copies and cost. Cross-account service integration is design-only here.
7. **Deadline:** `300 + 24 + 45 + 6 = 375` seconds, or 6:15, missing five minutes. At 180 seconds of worst-case wait, the model gives 255 seconds, or 4:15, leaving 45 seconds. That assumes the same 30 MB batch and sustained transfer rate. Measure real batch-size response, queue/worker delay, retries, report publication, event time and late correction. A stream changes waiting/replay possibilities but does not by itself guarantee finance reconciliation.
8. **Small files:** A one-number output can scan much more data and still include an invalid source. Stage files with immutable identity, validation and expected-source manifest; publish only a reconciled version. Compare partition pruning, safe compaction and columnar conversion with complete-row expected results and source hashes. Measure scanned bytes and full costs as well as correctness. Do not change a chart filter until an unaccepted file merely disappears from view while remaining in the published source.

Across the cases, a source receipt, query success, chart display and business acceptance are separate. Existing local drills cover narrow arithmetic, SQLite joins and CSV/Parquet semantics; they do not verify Lake Formation, DataSync, Transfer Family, Glue, Athena or Quick Sight in AWS.
