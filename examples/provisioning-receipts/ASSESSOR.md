# Assessor reasoning: provisioning receipts

Read after an independent attempt. These fictional cases test explanation and changed-condition reasoning; the local program checks only the supplied receipt fields.

1. **Image shelf:** A passing image pipeline creates a candidate image; distribution makes it available to selected destinations; a deployment still has to select and launch the exact reviewed artifact. Match the immutable digest or AMI identity at build, target specification and observed instance/task, then test behavior. A green build cannot prove the running worker changed.
2. **Two owners:** The backend must have one infrastructure owner. In this lab, Amplify Gen 2/CDK synthesizes CloudFormation-managed backend resources while Terraform owns Amplify Hosting. Do not let both manage the same table. A CloudFormation change set or Terraform plan previews possible resource actions subject to its tool and state; neither validates the customer's booking or a safe schema transition.
3. **First failed boundary:** Use the specific failed resource's stack event/status reason, selected subnet's actual free-address/capacity requirements and target account/Region to investigate address exhaustion. For an access error, inspect the denied action, resource, acting principal, relevant policy/guardrail and event context before making a scoped change. A rollback symptom may be downstream of an earlier failure. Re-run the affected test/plan and review the new diff before any retry.
4. **Three destinations:** Record the intended account/Region matrix, operation ID, failed-instance count and each instance's detailed status/reason. One `OUTDATED` instance is a partial deployment even if the top-level operation says `SUCCEEDED` under tolerated failures. Fix the cause, then retry only the appropriate scope and verify exact artifact and customer result.
5. **Share or create:** StackSets provisions stacks in chosen target accounts/Regions. RAM grants use of an existing supported resource to principals while the source account retains ownership. Verify shareable type, share Region, recipient/permission path and the consumer's own IAM/organization guardrails. An unsupported resource needs another design, such as explicit per-account provisioning or a service-specific sharing mechanism; do not assume RAM copies it.
6. **Traffic and customer:** A missing confirmed booking fails the business gate. Stop further exposure where the chosen controller permits, record the incident interval, preserve evidence and reconcile data/external effects. A traffic rollback does not automatically reverse schema changes or external sends; choose compatible previous code or a tested roll-forward repair according to the actual state.
7. **Toolchain transfer:** Git records source and review history, Terraform manages its selected Hosting resources/state, and Gen 2/CDK/CloudFormation manages its backend. The trigger or hosting branch connection is scoped to a selected application/repository; inspect and disable the publishing route for that application if desired. GitHub itself does not deploy every repository to Amplify automatically.

The model intentionally does not interpret real CloudFormation events, StackSet permission modes, account policies, subnet capacities, Image Builder pipelines or deployment controllers. Its all-green result is an internal consistency check on supplied facts, not operational acceptance.
