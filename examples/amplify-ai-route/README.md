# Decide whether the bakery needs an AI route

Read [Unit 26's AI-route lesson](../../reader/BOOK-LOCATORS.md#book-9c1c5544f5e73527) and the [four-pillar atlas](../../docs/AMPLIFY-CAPABILITY-ATLAS.md). These are fictional **design-only** cases. No model, Amplify AI route, knowledge base or AWS resource is created. Write your decision before reading the [assessor](ASSESSOR.md).

For each case, record the customer's promise, smallest sufficient path, actor and private-data check, resource owner, one positive and one forbidden result, request/retention meters, stop condition and the evidence that would change your choice. Keep cloud provisioning on paper until the selected account, full-run cost, spending and reserve limits, and cleanup have been reviewed.

1. **The answer is already on the menu.** Customers ask for today's opening hours. A contractor proposes a public generation route because a chat widget looks modern. Compare a static answer with generation. If hours change daily, what source must be authoritative and how would you test a stale answer?
2. **An order explanation is private.** Alice asks why order `A17` is delayed. Bob, who is also signed in, calls the same generation route with `A17`. The route uses an `authenticated` rule. The browser sends an `orderId` and a text prompt. Identify the missing server-side decision. State exactly what a second-user test must call and deny.
3. **One answer becomes a conversation.** Alice asks three follow-up questions. The product owner wants yesterday's conversation restored after sign-in, but deleted after a short retention period. Compare generation and conversation routes. Name the stored records, owner check, deletion evidence and cost meters that change.
4. **The helpful refund sentence.** A model returns “I refunded your order” after reading a delayed-order summary. No refund system was called. Later someone proposes a model tool named `issueRefund`. Separate answer wording, approved business effect and observed provider result. What actor/target/amount/approval/retry controls must remain outside the model's authority?
5. **The quiet knowledge base.** The owner uploads manuals to a Bedrock Knowledge Base using the documented default OpenSearch Serverless path. Nobody asks a question for two days. The worksheet includes only model tokens for ten test prompts and claims the USD 5 run gate passes. What resource and lifetime are omitted? Compare a small curated authorized excerpt path with a retrieval store for this trial.
6. **The diagnostic log.** A teammate enables Bedrock model invocation logging to debug a failed answer, then pastes a private order and email address into the prompt. What may be retained, where, and who should inspect it? Decide what sanitized test and narrower observability would answer the immediate question without assuming logs are free or private by default.
7. **A model or Region changes.** A new model gives more fluent explanations but occasionally invents a delivery deadline. The team shows a green build and a lower per-input-token price. Define an evaluation set with known orders, wrong-user attempts, uncertain cases and changed output lengths. What complete cost and customer result must be compared before switching?

**Codex review.** Ask Codex to mark each proposed security or pricing claim as documented, an inference or unknown. Have it generate a counterexample for every chosen route and identify the next read-only check. Verify its AWS-specific assertions with current official docs and any account-specific facts before using them. Do not submit real customer text, raw invocation logs, credentials or live approvals to this packet.
