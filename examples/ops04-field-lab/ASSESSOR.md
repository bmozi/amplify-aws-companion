# Assessor notes for the Field Lab OPS 04 review

Keep these notes separate from the first attempt. Assess the reader's boundary reasoning, not whether they name a favorite AWS product.

1. The fixture says 100 successful static page loads, but supplies no total number of page-load attempts. It therefore **does not support a page-load success fraction**; 100 is a count, not a denominator. This deliberate trap matters: a green graph of successful loads can coexist with unknown load failures. The note-save fixture does give 20 complete attempts and 16 refreshed confirmations, so its bounded confirmation fraction is 16/20, or 80%. Four attempts lack confirmation at the review point. They may be failures, delayed updates or unresolved observations; the fixture does not locate the cause. If a reader assumes 100 page attempts, ask where that denominator came from.
2. After the note-attempt feed stops at event fifteen, the full-window save fraction is not 16/20 from that incomplete feed. The historical complete fixture and the changed incomplete fixture are different evidence states; do not silently carry the old completeness claim into the changed case. The 100 successful page-load count remains as stated, but still lacks its attempt denominator. Propose an independent expected-event counter, heartbeat, synthetic path or authoritative record comparison with its own coverage and cost. A heartbeat says the pipeline is active, not that all business events arrived.
3. Expired Cognito session is plausible but unproved. A time-matched sign-in/token-renewal failure or authenticated-request rejection could help; absence in a sampled trace would not disprove it. Distinguish AppSync authorization by the returned error class and a scoped deny/allow test. Distinguish a write problem by resolver/data-service outcome and a refreshed read under the same intended owner. A real operator would verify actual service configuration and avoid logging tokens or note contents.
4. Map the five AWS practices to the one promise: completed private note as KPI; application result and coverage telemetry; signed-in user or synthetic observation; dependency-specific evidence; and only then cross-boundary correlation. No source link alone proves installed telemetry or end-to-end trace completeness. A RUM/canary choice introduces identity, privacy, retention and price work against the account owner's chosen estimate limit and credit reserve. Current classic CloudWatch versus Omni setup and effective permissions are unknown without account access.
5. The executable [local cases](cases.json) add a third state: a green heartbeat with five independently known missing attempt events. The checker correctly refuses a full-window rate even though 12 of 15 seen attempts have confirmations. Both attempt and confirmation windows must be closed; duplicate IDs and unmatched confirmations need investigation rather than silent arithmetic. The invented independent ledger is an assumption in the fixture, not evidence that the real app has one. The local test does not prove telemetry delivery or durable AWS persistence.

**Needs revision:** A response calls 100/100 page-load success without an attempt count; calls a healthy static page a healthy private notebook; treats an API 200 or UI “Saved” message as confirmed persistence; converts missing telemetry to zero failures; declares Cognito the cause; or claims a proposed AWS monitor already exists. A sufficient design-only answer preserves each evidence boundary, computes only the supported 80% fraction, identifies the incomplete feed and gives bounded next observations. This is not an independent learner score, live monitoring result or certification-readiness claim.
