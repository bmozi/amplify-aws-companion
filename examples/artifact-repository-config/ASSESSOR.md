# Assessor notes: artifact repository configuration

Use after a learner has recorded an initial design. These notes describe defensible reasoning, not the only answer. Give credit for named assumptions and evidence. A service name without artifact identity, publisher/consumer, trust, retention, cost and a falsifying test is incomplete.

1. **Internal library:** CodeArtifact is a native package repository for supported package formats such as npm. A domain groups repositories and shared asset/encryption/policy scope; repository endpoints and upstream choices shape package resolution. Pin dependencies and review upstream provenance. Configure package-origin behavior so the trusted publication path is clear. A public connection is a dependency source, not a security review. Test clean resolution of the pinned package and a rejected unauthorized publish.
2. **Moved tag:** ECR is the image store. Record the image digest in the tested release record and deploy that immutable identity where supported. Configure tag mutability if the process expects a tag to reject overwrite; do not assume a tag is immutable by default. Test a repeat push and compare the deployed digest to the approved receipt.
3. **Public ZIP:** S3 fits an object bundle; keep the build artifact private and publish selected site contents through a deliberately designed origin. Block public access on the artifact bucket, use bucket-owner-enforced ownership in the ordinary case, and use policies for access. Enable versioning when its recovery value justifies retained storage and lifecycle work. Test intended read and denied anonymous access on the private store.
4. **Image retention:** “Older than 30 days” can delete the only usable rollback. Keep releases according to deployment and recovery evidence, use separate tags or another explicit protection criterion, and preview the ECR lifecycle selection. The service can take time to make eligible images expire; storage does not necessarily fall immediately. Reconcile the policy preview with every deployment still in service and required recovery target.
5. **Private build:** A timeout is not evidence of an IAM denial. Trace DNS, route, firewall, endpoint/NAT and service endpoint reachability separately from authorization. Grant the build's temporary role only the package read needed for dependency resolution; publishing should be a separate role/action. Test a known allowed read, a denied publish and successful network retrieval without broadening policy.
6. **Account boundary:** Multiple layouts can work. Name the repository and key owner, trust path, cross-account resource policy and data-sharing intent. Keep organization controls separate from workload IAM. Test a narrowly allowed pull and explicit denied push and production deploy. This remains a fictional exercise; this exercise does not create Organizations policies or cross-account infrastructure.

## Evidence limits

The cases establish design reasoning and primary-source links in the manuscript. They do not prove current action/resource policies, region availability, successful package resolution, actual image immutability, lifecycle outcomes, cross-account trust, current prices or learner mastery. For a live test, first check the selected account, scoped identity, permissions, plan, full-run estimate, owner-chosen limit and credit reserve, cleanup and billing evidence. No live run is included here.
