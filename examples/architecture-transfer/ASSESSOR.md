# Assessor reasoning for the three-context transfer

Read this after preserving the first attempt. These are defensible answers under the fictional facts, not a calibrated scoring key or observed learner result. For each case, a sound answer must name an observation that could reject its choice. Do not award a service name alone.

For the [local contract walk](README.md#watch-three-different-promises-in-one-local-run), the expected JSON reports one retained repair-like booking after a lost reply and process replacement; a school owner denied after upload and scan pass but allowed after human approval; and colliding tenant record IDs separated by trusted fixture scope and warm/cold cache keys. Its three `copying_rule_would_miss` fields are part of the answer, not decorative output. A learner should say that the booking fixture does **not** know the external technician scheduler's effect, school read denial does **not** cover a direct object URL, and tenant query/cache checks do **not** prove export, restore, authentication or completion fairness. If the command fails, inspect the failing path; do not count a printed field from an earlier run as current evidence.

1. **Repair retry:** The acceptance record and retry identity must lead to one intended request, and the worker must avoid multiplying the assignment. A timeout does not tell us whether the external scheduler completed an assignment. Query or reconcile using a stable provider/business identity before another effect. A second blind call may double assign. The local outbox or transactional fixture is narrower than a real scheduler guarantee. Count retained retry records, queue attempts, worker time and failure logs before a cloud run.
2. **School scan:** The intake receipt says private bytes arrived; approval says a distinct human accepted a specific scanned version for release. Scan pass alone cannot authorize owner download. Test a direct owner request for the unapproved version and a reviewer request outside the assigned scope, expecting denials. A later human decision must bind the exact version, not the filename alone. These are designed checks, not observed AWS permissions.
3. **School direct link:** No. The normal application route is only one path. Inventory previously issued URLs, object versions, CDN/cache paths and copies. A proposed withdrawal must address future reads along every controlled path and state what cannot be revoked from an already downloaded copy. The local A04 route cannot observe an emailed object URL.
4. **Tenant recovery:** Whole-table replacement contradicts B's preservation promise. One option is isolated restore plus exact tenant selection, validation and guarded merge; another is a selected dedicated data boundary with its own restore process. Either must reconcile files, workflow state and external effects as applicable. Compare measured recovery time, data loss, tenant denials, duplicate effects, retained backup/storage and operating cost. Dedicated data does not isolate a shared cache or worker by itself.
5. **Noisy customer:** Correctness of authorization may hold while timely completion fails. Inspect worker capacity and the database/queue path shared by both tenants, including in-flight work and retry load. A fair-queue or scheduling mechanism can be a candidate, but it cannot repair an undersized shared database, untrusted group identifiers or a deadline already breached. Measure per-tenant accepted-to-complete time and full-path cost before choosing.
6. **Changed business:** A franchise role might be scoped to one or more shop IDs within the same provider; a district reviewer might have an explicit assignment across several school IDs and approved document versions. A string comparison on a group label cannot replace those distinct authorization relations. Test a neighboring franchise's request and an unassigned school's document as denied, while the intended cross-school review path is allowed only for its assigned reviewer and approved scope.

**Museum transfer:** The common questions still apply, but the result changes from private owner access to a public selected release. An incomplete image-variant set must remain unpublished; versioned URLs or a selected manifest can help keep one coherent revision. Cache propagation and already downloaded copies complicate withdrawal. Compare public and private origin paths, selection, egress and retained variants. Do not infer CDN invalidation timing or origin policy from the local publication fixture.

If a learner chooses a different design, ask whether it meets the same stated promise and whether the proposed rejection test could expose its failure. Record the first answer, source checks, help received and changed-case result separately. An assessor still needs an independent learner attempt to learn whether this packet teaches effectively.
