# Assessor reasoning: pipeline receipts

Read after an independent first attempt. The local receipt program is deliberately narrower than these design questions; a green fictional packet is only internally consistent.

1. **Repository/artifact:** Git records the reviewed source revision; an artifact repository holds the built release bytes or image. Carry an immutable artifact identity through tests and promotion. A second build can differ when dependencies, tools, environment or generated inputs differ even if source is unchanged. Check the downstream artifact, not the version label alone.
2. **Events:** PR checks give fast feedback on the proposed revision. The merged revision and release artifact need matching post-merge evidence, especially where merge result or build inputs can change. This repository's Amplify publisher is `workflow_dispatch` only and additionally gated by a variable and explicit input; ordinary Git pushes do not automatically publish every repository or branch.
3. **Secrets:** Keep a supplier credential in an appropriate secret service such as Secrets Manager or Parameter Store, accessed by the selected build role with only needed permissions. CodeBuild buildspec guidance discourages plaintext secret environment variables and warns that transforming a masked secret can expose the transformed value in logs. A secret being masked in one format does not prove the build cannot leak it.
4. **Exit/report:** Both a nonzero exit and a report with failed tests block the candidate. Zero tests is not a passed required test. Review command exit, test count, failed/skipped/inconclusive cases, report identity and artifact binding; define how the CI platform handles `finally`, retries and continued-on-failure commands.
5. **Coverage/health:** Coverage is evidence that selected code lines or branches were executed by tests under that tool's measurement, not that the right requirements were asserted. Exit zero says a process ended successfully by its own convention; it does not prove that a live booking path is correct. Check consent denial leaves no outbox record and consented booking produces the exact expected record and message.
6. **Load:** Use an authorized isolated target with representative data and dependencies, a declared load profile and fixed duration. Observe latency distribution, errors, throughput, queue/dependency saturation and customer correctness; set a stop threshold and capture resource/cost/cleanup evidence. Review the account owner's chosen estimate limit and credit reserve before any live run. A local toy result is not an AWS capacity measurement.
7. **AWS test:** Provision only named disposable resources using a scoped role; isolate test identities/data and parallel names, record exact account/Region and API result, and clean up even after failure. Check residual resources and delayed billing. The current local lab crosses SQLite and loopback HTTP boundaries, not IAM, S3, Lambda, network or cloud cleanup.
8. **Deploy:** Pick a strategy supported by the selected runtime and observe candidate-specific behavior. A missing confirmed booking is a failed business invariant despite HTTP 200. Stop expansion, preserve evidence and reconcile records/effects. Traffic rollback may be incompatible with a changed schema; use a tested compatible old version or deliberate roll-forward repair.

The source packet does not implement CodeBuild, CodePipeline, GitHub CI, coverage instrumentation, security scanning, an AWS-backed test, actual load or a deploy controller. The six local tests assess only receipt logic; the older consent lab executes real local unit/integration/acceptance boundaries. Neither establishes independent learner mastery or a cloud release.
