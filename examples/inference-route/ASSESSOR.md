# Inference-route assessor reasoning

Read after completing the [six cases](README.md). More than one architecture can pass if it names the missing measurement and a stop condition. The useful answer connects the caller's deadline, arrival pattern, payload/runtime, data authority and full cost to a selected mechanism.

1. **Counter:** A real-time endpoint is the first candidate for sustained interactive traffic and a strict deadline. It still needs peak-load measurement, model-version control and an application fallback. “Real-time” is a service category, not proof of the shop's latency target. On-demand serverless may be considered only after its cold-start tail and limits are shown to fit; batch and asynchronous routes do not provide the promised immediate suggestion.
2. **Weekly:** On-demand serverless is a candidate because waiting and cold starts are allowed. Verify model, memory, payload, runtime, Region and actual wait. A continuously provisioned endpoint can waste idle capacity. Serverless provisioned concurrency might lower wait but adds capacity cost and defeats a simple “pay only when invoked” story.
3. **Recording:** Asynchronous inference is a candidate for a long request when a later result is acceptable. The proposed application is incomplete until it can issue a stable job receipt, display status, authenticate result reads, expire inputs/outputs and reconcile failed or duplicated attempts. Do not expose a stored object through an unscoped link. Test current size/time limits and processing latency before committing.
4. **Monthly:** Batch transform is the natural first candidate for an offline complete dataset without a persistent endpoint. Define input/output manifests, per-record errors, version, rerun behavior and the next-morning completion check. A batch job finishing does not prove the model's predictions are correct.
5. **Changed promise:** Compare measured on-demand tail behavior with a bounded real-time configuration or provisioned concurrency, including burst capacity, time target and idle/provisioned cost. If none fits the budget and deadline, change the customer promise or model/serving design. A label such as “serverless” does not override an observed miss.
6. **Action:** No serving option grants business authority or model quality. Preserve the technician's contrary observation, assess false negatives on representative data, identify the approved warranty rule and who can decide, and test an appeal path. A generated classification is evidence for review, not permission to deny a claim.

The [AWS option guide](https://docs.aws.amazon.com/sagemaker/latest/dg/deploy-model-options.html), [serverless guide](https://docs.aws.amazon.com/sagemaker/latest/dg/serverless-endpoints.html) and [asynchronous guide](https://docs.aws.amazon.com/sagemaker/latest/dg/async-inference.html) are the current service basis. This answer key is authored reasoning, not a run against SageMaker AI or a learner result. Before a live trial, choose a supported Region/model, measure full-path latency and quality, price all retained resources against the account owner's chosen estimate limit and credit reserve, and record cleanup. The exercise does not authorize deployment.
