# Assessor notes: the borrowed key

Compare the reader's explanation with the relevant condition, not just the time printed on the link. The AWS [presigned URL guide](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html) is the source for the S3 behaviors summarized here.

1. **10:30 is too late for that role session.** A presigned URL created with temporary credentials cannot remain valid beyond those credentials, even if the requested URL lifetime is longer. Inspect the actual signing session and its expiration, along with the URL's own parameters and request time. Do not infer that all requests before 10:20 must succeed: permissions and other controls still apply.
2. **A download already started can continue after URL expiration.** AWS checks the URL expiration when the HTTP request begins. A fresh request after expiration, including a retry after a dropped connection, fails because the URL is expired. This does not promise that the original transfer will finish: unrelated network, client, or service failures remain possible.
3. **The first use does not by itself consume an S3 presigned URL.** A valid link can generally be used repeatedly until expiration, subject to credentials and other controls. Possession is not proof of the intended recipient's identity. If a business requirement demands one-time or recipient-specific access, design and test a separate control; do not label the URL itself one-time.
4. **A later expiration is not an unconditional grant.** A valid signature and unexpired credentials do not override an applicable explicit deny. Inspect the actual principal, requested operation and resource, policy conditions, request context, and relevant audit evidence; this paper case does not evaluate IAM or determine an observed denial.
5. **An upload to the same key can replace the current object.** Determine the bucket's actual versioning state, prior versions and retention, authorization and recovery procedure before promising recovery. Versioning and lifecycle rules may affect what is retained; the local exercise has not tested them.

A useful negative test names the principal or bearer, exact object and operation, expected result, time and policy assumptions, and the evidence that would falsify the claim. A test plan is not the result of executing it. Avoid recording the complete URL in logs or examples.
