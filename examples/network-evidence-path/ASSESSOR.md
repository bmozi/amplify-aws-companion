# Assessor reasoning: whole-request network evidence

Read after an independent attempt. The observations are fictional. The answer is a method for narrowing causes, not a claim that a real AWS request took this route.

1. **Cached direction:** The customer's resolver answer is the operative clue. Public authoritative query logs see only queries reaching Route 53; a cached response may generate no new query. A lower TTL must be in place early enough to affect already-cached answers. Observe the actual client resolver and customer request before declaring a cutover.
2. **DNS policies:** Weighted routing distributes authoritative responses by weight; failover routing depends on the configured health decision; latency routing aims to choose an endpoint based on AWS's measured latency model. None forces cached resolvers to ask again immediately or guarantees a completed application request. Inspect record/health configuration and actual client answers before treating a DNS change as recovery.
3. **Stale public asset:** A cache hit points first to cache policy, key, TTL and object version. A versioned URL often gives an explicit new identity; invalidation can remove old cached objects but has operational and possible price implications. Disabling caching shifts load and cost to origin. Confirm that the new URL or post-change edge response serves the intended version.
4. **Private status:** A shared cache key can serve one customer's response to another if the cache policy/origin design is wrong. Treat it as a data-protection incident until scoped. Check whether the response is cached, its key and forwarded identity, and whether the origin itself enforces ownership. A cache bypass for private responses may be safer than attempting to enumerate every identity variation; test cross-customer denial.
5. **WAF block:** The matching WAF decision is the first observed stop. Verify association, rule ID, labels, sampled/logged scope, timestamp and intended request before a narrow rule change. The absence of an origin record is consistent with an edge block but alone proves little. Changing an origin security group cannot override a prior WAF block.
6. **Accepted flow:** `ACCEPT` describes the matched interface flow, not TLS, target health or business success. The ALB 503 and unhealthy target move investigation to target registration/health, app readiness, capacity and dependencies. Keep route/rules in the hypothesis set until the records match the same path and time; a broad firewall opening does not repair an unhealthy process.
7. **One subnet:** Select the most-specific matching route in the actual associated table. A broken specific target is not bypassed by a broader default route. Check target state, route association, reverse path and unaffected subnet comparison. Change one route/association in a bounded window and retain a rollback that restores the earlier state.
8. **Private API:** Endpoint state alone does not show that this caller resolved its DNS to the endpoint, traversed permitted traffic rules or was authorized by endpoint and service policies. A service denial is evidence of a responder, but inspect the precise service error and effective principal. Positive and negative requests from intended and unintended roles are required before an access claim.
9. **Hybrid tunnel:** Tunnel state only covers the tunnel's own health indication. Overlapping CIDRs and missing advertisements/return routes can still prevent useful traffic. Readdressing preserves simpler routing but may have migration cost; translation can avoid immediate readdressing while adding operational complexity. This is design-only here, with no VPN created.
10. **Protection layers:** Resolver DNS Firewall filters DNS queries through configured Resolver paths; WAF evaluates supported web requests at associated resources; Network Firewall applies network traffic rules at its inserted VPC path. Each needs its own association/routing and logging scope. None should be credited for traffic that never crosses it.
11. **Cost and alarm:** Confirm source/destination, route-table association and S3 request path. A same-Region S3 gateway endpoint is a candidate for eligible VPC traffic; an interface endpoint is a different paid network path, and NAT can have hourly and processed-byte charges. Estimate actual Region/service dimensions and data transfer/logging, then compare before/after usage without sacrificing multi-AZ requirements. A CloudWatch alarm identifies its metric/period/dimensions, not the causal packet. Upload growth is a hypothesis until route and bill evidence agree.

Across all cases, distinguish a component's report from an end-to-end customer result. A useful answer names what would disprove its leading explanation. No independent learner, AWS service or billing validation is recorded.
