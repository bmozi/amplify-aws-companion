# Find the first failed boundary

The repair shop's customers report “the site is broken.” Read the [whole-request lesson](../../reader/BOOK-LOCATORS.md#book-4448eae645ea531e). For each fictional case, write (1) what is observed for the same attempt, (2) the earliest boundary **proved** failed or “unknown,” (3) two plausible explanations, (4) one read-only check that separates them, and (5) a safe, bounded change and rollback condition. Keep a first answer before the [assessor reasoning](ASSESSOR.md). These are design cases, not AWS console instructions or certification questions.

| Case | Changed observation | Your decision |
| --- | --- | --- |
| 1. Cached direction | Route 53's new authoritative answer is healthy, but one customer's resolver still returns the old address within the previous TTL. | Which answer did that customer use? What can the Route 53 query log omit? Compare a cached-client wait/versioned transition with shortening TTL before a *future* change. |
| 2. Three DNS policies | An operator proposes a weighted record to move every customer immediately; another proposes failover routing; a third needs a latency-oriented choice. | State what each policy tries to choose, which health and cache limits apply, and what observation would prove customer use of the new destination. |
| 3. Stale public asset | CloudFront returns `Hit` for yesterday's public status image while the origin has today's version. | Is origin repair the first move? Compare versioned asset naming, TTL and invalidation, including cost and origin-load effects. |
| 4. Private status at the edge | A private customer status response appears under a cache key shared by customers. | What data risk arises? Which cache-key, forwarding and origin authorization checks precede a new cache policy? A fast hit is not a correct hit. |
| 5. Web-filter block | A matching WAF log says `BLOCK`; no origin access record appears for the attempt. | Where did this request stop? What rule-scope evidence would justify a narrow correction? Why is an origin security-group change misplaced? |
| 6. Accepted flow, failed task | A matched VPC Flow Log says `ACCEPT`; an ALB access record says 503 and target health is failing. | What did `ACCEPT` prove? Separate subnet route/rules, target availability and application capacity before a change. |
| 7. One subnet fails | The affected subnet's associated route table contains a more-specific blackhole path; an adjacent subnet's table does not. | Which destination matches? Why does its healthy default route not rescue it? Check the return route and the rollback before changing association or target. |
| 8. Private AWS API | An interface endpoint reports `available`, but the workload receives a service authorization denial. | Separate endpoint DNS/reachability, endpoint policy, IAM/resource policy and service response. Which allowed and denied request would prove the intended boundary? |
| 9. Hybrid tunnel | Site-to-Site VPN shows a tunnel up, but an office CIDR overlaps a VPC range and the return route is unverified. | Why is tunnel state insufficient? Compare address translation/readdressing and route design; keep this case design-only. |
| 10. Protection layers | A teammate suggests Route 53 Resolver DNS Firewall to block a bad web request and AWS WAF to block private outbound DNS queries. | Match DNS query, web request and VPC traffic to DNS Firewall, WAF and Network Firewall. Which coverage/log is needed at each layer? |
| 11. Cost and alarm | NAT processed bytes and a network alarm rise while same-Region S3 uploads grow. One proposal adds an S3 gateway endpoint; another sends all traffic through an interface endpoint. | Check the real route and destination first. Compare eligible traffic, endpoint policy, NAT/endpoint hours and bytes, logging/transfer charges, multi-AZ resilience, and the alarm's dimensions/time. What would falsify the proposed saving? |

For cases 6–8, run the [loopback and longest-prefix diagnostic](../network-diagnostics/README.md); it demonstrates HTTP-versus-transport differences and route selection, not AWS Flow Logs or endpoint policy. For case 11, run the [fictional route-cost worksheet](../network-cost-routing/README.md) and [workload evidence review](../network-workload-review/README.md). Explain where their invented prices and observations stop. Ask Codex to challenge the earliest-boundary claim and request a falsifying observation; never paste credentials, private hostnames or customer data into a prompt.

For a real AWS exercise, first verify the selected account/Region, plan impact, scoped non-root identity, a complete estimate against spending and reserve limits chosen for the account, stop condition, cleanup and delayed billing. Query logging, WAF, Network Firewall, NAT and endpoints can have separate charges. This packet enables none of them. The hybrid and multi-account choices remain design-only here. No live network, cost or learner outcome is claimed.
