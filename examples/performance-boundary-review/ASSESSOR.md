# Assessor notes — whole-path performance

Internal editorial criteria, not scored learner results or AWS benchmarks. Require a disconfirming observation, whole-path cost and rollback for each proposal.

1. Average CPU can hide one hot process. Inspect the same affected requests, per-worker CPU, serialization and wait profile. More cores help only if the work can use them; tags identify scope but are not a performance diagnosis. Compare actual customer result with a compatible, same-workload candidate.
2. `6,000 × 4 KiB ÷ 1,024 = 23.4375 MiB/s` attempted. Supplied volume IOPS is exceeded; throughput and instance ceilings are not. Check applicable `VolumeIOPSExceededCheck`, `VolumeThroughputExceededCheck`, supported instance EBS-limit metrics, latency and queue in the same interval. A different instance ceiling or first-read behavior could make a volume-only change insufficient.
3. The supplied instance IOPS ceiling is exceeded while the volume's is not. Check the instance EBS metrics, guest/driver path and, for a restored volume, first-read effects. A volume IOPS purchase alone does not remove an instance cap.
4. The 8 TiB/80 Mbit/s ideal lower bound exceeds five days before overhead; no transfer product can create office uplink capacity. Multipart helps one large object and retry/concurrency choices; Transfer Acceleration addresses a geographic path where eligible; DataSync manages supported transfer tasks; grouping changes independent-object semantics and may add buffering/compute. Price bytes, requests, services, retained data and cleanup.
5. EFS is the NFS candidate; FSx for Windows File Server is the SMB/AD candidate. S3 Files is a candidate when S3 stays authoritative and NFS writers need the same dataset, but its synchronization, conflict, initial-directory access, active high-performance storage and operation costs must be tested. Compare encryption, identities and client network scope for each. A generic S3 bucket is not interchangeable with a mounted file system.
6. Measure connection acquisition separately from query execution and locks. RDS Proxy can reduce backend connection demand when sessions are shareable; it does not remove scans or locks. Explain that the official exam text still says Performance Insights while AWS now directs users to Database Insights. Do not infer that a database instance needs more CPU from connection count alone.
7. A closely coupled simulation may benefit from a placement-group test if compatible instances/capacity and failure design allow it. The RDS-waiting web API has no shown need. Placement choices can trade fault isolation and launch flexibility for network placement; keep an AZ-failure plan.
8. The modeled 750 ms still misses the target; 580 ms meets it only if the other fictional stages stay fixed. A cross-tenant result fails correctness regardless of speed. Repeat representative same-mix measurements and inspect tails, errors, quota/failure margin and total cost. Retain rollback and compare an independently defined customer outcome.
