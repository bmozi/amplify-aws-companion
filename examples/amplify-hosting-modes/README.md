# Does the page need a server when the visitor arrives?

Maya's repair guide and private notebook share a website. The guide text is the same for everyone. The notebook loads a static React page, then makes identity-scoped Data calls from the browser. A teammate proposes moving the entire app to server-side rendering (SSR) because “private means server-side.” Start with the business promise, not the framework name. This exercise changes one need at a time and uses no AWS resources.

Read the [illustrated lesson](../../reader/BOOK-LOCATORS.md#book-88245f0f31eae765), write your decisions, then open [assessor reasoning](ASSESSOR.md). For each case, state the chosen route, data authority, release path, likely new meters and one observation that could disprove your choice.

1. **The private note.** A signed-in customer must see only their own saved note *after* the page loads. Existing client Auth/Data calls meet the user experience if their authorization is correct. Does that require SSR? What actual second-user negative check is still needed?
2. **The first response changes.** An external client requires the first HTML response to contain a current repair-status summary specific to its authenticated account. Would a public static guide plus browser fetch satisfy the exact new contract? If SSR is selected, who authenticates the server request, which data route may it call, and what two-user/cache test is required? An alternative API or pre-rendering proposal must meet the stated first-response and freshness rule before it can replace SSR.
3. **The delivery shortcut.** The team reuses this repository's manual `frontend.zip` workflow for a new SSR framework. Its build produces compute code as well as static files. AWS says manual deployments do not support SSR. Identify the failed assumption, then define the source revision, framework/adapter output, release identity, hosting job, served-page and backend checks for a supported route. Do not describe a successful static upload as proof that SSR ran.
4. **The deceptively small estimate.** Use the October 19, 2026 [public Amplify pricing page](https://aws.amazon.com/amplify/pricing/) outside any free allowance. A fictional 30-day design serves 5 GB, retains an extra 0.01 GB of Hosting build data, and, if SSR is selected, processes 100,000 SSR requests consuming 6 GB-hours. Use the listed $0.15/GB transfer, $0.023/GB-month storage, $0.30/million SSR requests and $0.20/GB-hour SSR duration rates. Calculate the listed Hosting components for static and SSR. Now replace 5 GB served with 40 GB. Compare each subtotal with a whole-run limit you choose for the fictional exercise. Can either subtotal alone justify a launch? Name omitted meters and account facts.
5. **The shared shelf.** A cache shows Maya's status page to another signed-in user. A teammate points to a successful deployment job and the platform's managed cache policy. Explain why neither proves safe personalized caching. Which actual response, headers, route rule and two-user observations are needed? What immediate containment and correction would you propose for this *fictional* incident?

For a transfer case, imagine a public catalog with one personalized checkout fragment. Decide whether only that fragment needs a server-rendered route or whether a static shell plus an authorized API can meet the promise. Compare how each choice changes response timing, backend authority, caching, build/deploy method, testing and cost; a page can mix static and compute routes on a supported SSR platform. Ask Codex to challenge one assumed meter and one assumed permission. Keep its suggestion separate from evidence in the [learning record](../../curriculum/LEARNING-RECORD.md).

The calculations use listed public rates and *fictional quantities*. They are neither an eligible Free Tier assessment nor a current account quote. For a live run, estimate the **entire** selected workload and choose a spending ceiling and credit reserve for your account; this packet does not authorize SSR deployment. No server-rendered app, cache policy, identity, billing line or learner outcome was tested.

## Change who owns hosting

The earlier five cases changed *when HTML is rendered*. These cases change *who builds and owns the hosting road*. Read the [three-route lesson](../../reader/BOOK-LOCATORS.md#book-7f3911d418d814d9) and [AWS's self-managed preview warning](https://docs.amplify.aws/react/deploy-and-host/self-hosting/) before deciding. Make a three-column sketch: managed Git Hosting, this lab's manual Amplify API route, and preview self-managed hosting. For each case, state the resource owner, first cloud write, release trigger, off switch, likely cost meters, and a customer-path observation. Do not install `@aws-amplify/hosting` or run `ampx deploy` for these paper cases.

6. **A website already in the lab, hypothetically.** Assume the Terraform-managed Amplify app is serving a static ZIP on branch `lab`; the proposed GitHub publication flag is `false`. A teammate adds `amplify/hosting.ts` with `defineHosting()` and says it will “upgrade the same app.” Which resources and owners would now need inventory and reconciliation? Does the new file alone change the hosted page? The account's present app state is unverified.
7. **The compliance request.** A production customer needs direct CloudFront configuration and WAF control. A teammate points to self-managed hosting's CDK access and proposes immediate production rollout. What does AWS's preview status rule out as an evidence-backed production recommendation today? What supported alternatives or bounded evaluation questions should the team compare without promising one will fit?
8. **The second switch.** The existing GitHub workflow flag remains false. Another engineer proposes a self-managed `definePipeline()` with push triggering, or an external GitHub job that runs `ampx deploy`. Does the existing flag turn either route off? Which source connections, pipeline settings, AWS trust and active sessions must be checked before claiming a stop?
9. **The broad command.** An operator intends to change only frontend assets but copies a no-scope `npx ampx deploy --identifier my-app` from the getting-started page. The backend contains private notes. Which stacks may that command touch according to the preview guide, and what does `--frontend` change? Why does a local build or successful deployment command still not prove correct customer notes?
10. **The copied worksheet.** A proposed preview self-managed static deployment reuses the manual Amplify Hosting worksheet's USD 0.75023 Hosting subtotal and declares the whole run affordable. Name the separate S3/CloudFront, optional compute, logging, alarm, WAF, CI, retained-resource and backend questions. Can a run proceed with no current identity, credit balance, account-specific limit or complete selected-resource estimate?

For a numerical version of case 10, run the [fictional self-managed cost inventory](../costs/self-managed-hosting/README.md). Its default alarm and selected-feature negative controls show why a subtotal copied from managed Hosting cannot establish a self-managed budget.
