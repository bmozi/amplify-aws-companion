# A10 assessor: what the slot result proves

Keep this separate from the learner's first answer. Accept equivalent reasoning that identifies the missing boundary and a way to observe it.

1. Slot 2 is a **dispatch order**, not a time guarantee. The baseline virtual timeline gives B a finish at second 601 with round robin and 2401 with FIFO. If A1 grows from 600 to 1,200 seconds, B finishes at virtual second **1201** under round robin and **3001** under FIFO. The 1,800-second modeled difference remains, but neither result proves an actual customer deadline. Consider a maximum job duration, workload classes, reserved capacity or more workers, then measure waiting and completion by shop under a representative burst. These are options, not properties of this fixture.
2. In this code, after A1 is dispatched, Shop A remains at the front of the ready rotation. If B arrives then, A2 is selected for slot 2 and B1 for slot 3. The worker cannot preempt A1, and a newly arrived tenant does not jump ahead of a tenant already ready. A design that needs a stricter deadline may require reserved capacity or different job classes, with their own tradeoffs.
3. No. A shared database, external API or lock can make Shop B slow after fair dispatch. Measure queue age, dispatch-to-completion duration and customer-visible completion for each tenant, with controlled cardinality and privacy.
4. Per-process counters can each accept four Shop A jobs. A distributed version needs an authoritative shared admission decision, a stable request identity and a defined retry response. A rejection should not claim that a job was accepted; if acceptance is uncertain, reconcile by the stable ID before resubmitting.
5. The server derives the tenant from verified identity and current membership. Reject a conflicting request label before admission. An internal queue record should carry that trusted context. A queue name or partition key alone is not an authorization check.

In the architecture comparison, global FIFO is simple but places Shop B behind Shop A's burst. The demonstrated round robin improves dispatch opportunity with shared infrastructure, while the fixed four-job limit stops one waiting line from growing indefinitely. Dedicated worker capacity can isolate worker contention but does not automatically isolate shared data or external dependencies; it also introduces fixed cost and lifecycle work. Strong answers state a measurable customer objective, identify all shared bottlenecks, and choose based on evidence. Do not grade a learner as cloud-ready from this deterministic simulation alone.
