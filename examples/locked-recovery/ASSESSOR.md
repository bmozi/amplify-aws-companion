# Assessor: locked recovery

1. **S3 version:** S3 Object Lock protects the specified object version. It does not prevent creation of a new version or delete marker above it. The operator must locate and authorize reading the intended version, verify integrity and business identity, confirm decryption, and restore the application-visible path. Key loss remains a separate failure. [AWS Object Lock](https://docs.aws.amazon.com/AmazonS3/latest/userguide/object-lock.html), [considerations](https://docs.aws.amazon.com/AmazonS3/latest/userguide/object-lock-managing.html).
2. **Mode and hold:** S3 governance mode may be bypassed by an authorized principal using the required bypass action/header; compliance mode does not permit shortening or deletion during retention. A legal hold is independent and remains until an authorized action removes it. Check both the caller's permissions and the actual version state. [AWS Object Lock modes](https://docs.aws.amazon.com/AmazonS3/latest/userguide/object-lock.html).
3. **Snapshot:** EBS snapshot lock protects a snapshot from deletion while active, but says nothing about correct application files, available KMS keys, a bootable instance or malware-free data. Restore into a contained target, validate data and workload behavior, then choose a safe cutover. Governance and compliance modes have different unlock rules. [AWS snapshot-lock concepts](https://docs.aws.amazon.com/ebs/latest/userguide/snapshot-lock-concepts.html).
4. **Vault:** Backup Vault Lock governance mode can be managed by sufficiently authorized users. Compliance mode becomes immutable after its cooling-off period; a long or indefinite backup lifecycle can impose persistent cost. Review the exact grace time, recovery-point lifecycle and vault access before activation. This paper exercise does not create a locked vault. [AWS Vault Lock](https://docs.aws.amazon.com/aws-backup/latest/devguide/vault-lock.html).
5. **Clean point:** A locked Tuesday backup can faithfully preserve Monday's encrypted or corrupted data. Use attack timeline, backup timestamps, independent records, malware/forensic review and a contained restore to identify a clean candidate. Compare restored booking IDs and allowed customer actions before declaring useful recovery.
6. **Separate location:** Copy and restore need matching permissions, Region/account availability, encryption keys, data-location approval, retention handling and cost. A copy receipt is evidence of transfer; a customer-path restore is different evidence. Do not assume every service and resource type has identical cross-account backup support.

**Assessment boundary:** This packet is a source-grounded decision exercise. It has no AWS denial receipt, restore result, priced retention, legal validation or independent learner observation. Reject an answer that says only “make backups immutable” or proposes compliance mode before the retention and key plan has an accountable owner.
