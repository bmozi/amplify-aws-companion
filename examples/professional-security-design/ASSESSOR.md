# Assessor notes: professional security design

These are authored criteria for fictional cases, not observed AWS policy results, a calibrated exam rubric, or independent learner feedback. Accept a different architecture if it names the same independent boundaries and evidence.

1. **Directory to role:** External IdP authentication does not create an account assignment. Verify the intended user's provisioned identity/group, permission set, target account assignment and resulting session path. A similarly named role in another account is not the role this employee needs. Customer application login is a different path. A new assignment would be a future authorized configuration change, not a read-only check.
2. **Object and key:** A bucket-policy grant cannot repair missing KMS cross-account permission. For the production role, inspect the owner key policy, caller-account IAM permission, exact object/role scope, relevant denies and service integration. Expanding S3 to every object violates the stated approved-version boundary and does not solve the key gate. The employee's data-account role has a different policy path; do not merge their results. Test approved and adjacent objects only in an authorized environment.
3. **Network and TLS:** An HTTP 403 means some component returned an HTTP denial; first identify that component and request ID. The route, resource/subnet traffic rules and certificate evidence can support connection reachability and endpoint identity, not export authorization. Do not widen network access or bypass TLS. Inspect the intended record-level approval and effective S3/application policy for the denied adjacent export; the denial may be correct.
4. **Missing audit row:** A multi-Region organization trail does not by itself establish that S3 object data events were selected or delivered. Check trail and event-selector scope, account/Region/object/time, destination delivery and permissions before inferring absence of a read. A complete query over incomplete collection still has a coverage gap. CloudTrail management events and selected object data events answer different questions and can have different cost drivers.
5. **Departure and findings:** Remove future workforce access through the actual directory, provisioning and account assignment process; review outstanding sessions and other paths. A green CSPM result describes its configured control/resource/Region evaluation, not this employee's effective access or the delivery of every audit record. An Access Analyzer external-access finding concerns a resource-based policy relative to its zone of trust; it is not evidence that the departing employee used it. Verify the policy, intended exception, exposure owner, event-delivery monitoring and the restricted notification recipient before deciding what changed. Do not suppress or dismiss a finding to make the dashboard quiet.

For the transfer, a new bucket/Region requires explicit policy/key, event-selector, certificate, data-location, linked-Region and cost review. Using a role directly in the data account can centralize the human's account assignment there; a production application role needs a cross-account resource/key agreement and its own workload identity. Neither path eliminates the data owner's approval or the need to check forbidden adjacent access. No real policy, IdP, trail, alert delivery, certificate renewal or AWS cost was verified here.
