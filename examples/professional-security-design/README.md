# Professional security design: one export, several independent gates

Read [the integrated security lesson](../../reader/BOOK-LOCATORS.md#book-3c5e80806a4f57b6), [data protection](../../reader/BOOK-LOCATORS.md#book-825913145aea88a5), and [control evidence](../../reader/BOOK-LOCATORS.md#book-729bcef61bca9356). Maya's fictional production, data and security accounts belong to an organization; **this is design-only**. No real provider, policy, user, account, finding, certificate or customer data is supplied.

Maya approves export version `repair-2026-10-19-v3` for an employee who needs access to the data account. The employee's company uses an external workforce identity provider. A production application also has a separate, temporary role that may fetch that exact export for a one-time delivery. The export is stored in S3 under a customer-managed KMS key. The security team wants to know whether either reader accessed it, whether an adjacent export remained denied, and whether the evidence reached its restricted review destination. Do not treat the two readers as the same principal.

Write a decision table with columns: actor; identity source and session; target account/Region; required trust and grant; resource/key permission; network/TLS path; allowed check; denied check; event source and coverage; owner; cost and retained resource. Draw the employee and application paths separately. For each case below, state the **first missing gate**, the smallest read-only observation that would distinguish competing explanations, and what result would allow the reviewer to continue. Then read the [assessor notes](ASSESSOR.md).

| Case | Changed fact |
| --- | --- |
| 1. Directory to role | The external directory authenticates the employee, but her IAM Identity Center group has no assignment in the data account. Another employee has a production-account role with the same friendly name. |
| 2. Object and key | The production application's role has an owner bucket-policy grant to read the approved object, but the owner KMS key policy has no corresponding cross-account use permission. A teammate proposes granting all S3 objects to fix the error. |
| 3. Network and TLS | The employee's browser reaches an HTTPS endpoint with a valid certificate, but the application returns 403 for an adjacent export. A route, security group and subnet ACL all permit the connection. The teammate calls this a network outage. |
| 4. Missing audit row | A multi-Region organization trail exists. A reviewer cannot find an S3 object-level read for the export and concludes no one fetched it. No selected S3 data-event scope, trail delivery result or account/Region/resource/time join has been supplied. |
| 5. Departing employee and central finding | The employee leaves the company. A central Security Hub CSPM dashboard still shows a green control, while IAM Access Analyzer reports a resource policy with external access. An old role session may still exist. Explain what each observation can and cannot prove, who reviews access removal, and how a missed notification is detected. |

**Transfer:** The company adds a second Region and a new export bucket. Update the role and key grant, certificate and route assumptions, CloudTrail event selection, Access Analyzer zone of trust, Security Hub CSPM home/linked-Region scope, destination access and cost estimate. Do not infer inheritance from a dashboard label. Compare using a role in the data account with a production-account role plus cross-account resource/key policies; name the change in ownership and review work.
