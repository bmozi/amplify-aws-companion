# Assessor notes: Five checks before a request reaches data

This is an internal answer guide for the [five-case exercise](README.md), not a calibrated exam rubric. A good answer names the decision boundary and what its evidence can prove. Ask the learner to change one fact and revise the answer instead of rewarding service-name recall.

1. **Configuration and credentials:** A URL or region is usually ordinary configuration; a password is a secret. Keep it out of source, downloaded JavaScript and diagnostic output; limit which worker can retrieve it. Replacing the stored value does not replace the supplier's accepted value or refresh a warm consumer. Reconcile both ends, use bounded retries, and verify old-credential rejection. The local lab demonstrates controlled loopback fixtures, not Secrets Manager.
2. **Service endpoints:** A VPC endpoint is for a supported service path, not a universal private tunnel. A same-Region S3 gateway endpoint has different scope, route and price behavior from an interface endpoint for another service. A cross-Region destination changes eligibility and transfer questions. Check DNS, route association, resource and identity permissions, availability and complete current cost for the actual workload.
3. **Ports, protocols and traffic:** State source, destination, protocol and port. A security group is stateful; a network ACL is stateless and may need appropriate return rules. A route determines a next hop, not permission by itself. TLS checks the transport and server identity; the application separately authorizes a customer and record. Reproduce a meaningful path safely before changing rules.
4. **Application access:** Authentication establishes an identity for a configured flow. The application/API must validate the identity and enforce current record ownership; a request-supplied tenant or record ID is not authority. A delayed job needs explicit, durable business authorization and a defined response to changed membership. The local SQLite fixture tests only its stated method boundary, not Cognito or deployed storage controls.
5. **External threats:** SQL injection targets query interpretation; parameterized queries and careful application handling address that class. DDoS targets availability/capacity; edge/network protections, request limits and service capacity controls may help within their documented scope. A web firewall rule can match request patterns but cannot establish record ownership, and simple IP grouping can affect many legitimate users behind one carrier. Measure false blocks, preserve a rollback and do not call a design tested until the selected control has bounded evidence.

The exercise should leave explicit questions: which endpoint and feature is supported in the chosen Region, which identity and policy authorizes each hop, what cost and availability tradeoff the path creates, and whether selected controls affect a representative workload. No AWS service, firewall rule, secret, identity, scan or price was inspected or changed for this exercise. Independent learner responses remain uncollected.
