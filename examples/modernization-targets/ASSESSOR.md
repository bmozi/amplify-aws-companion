# Target and modernization assessor

Use this guide after writing your own answers. Several answers may work when they preserve the business contract and defend current service support, cost and operations. A suggested answer is not a scored learner result, certification prediction or live architecture test.

1. A low-change EC2 move may fit the deadline but leaves OS, patch and capacity work. Beanstalk can manage a supported deployment environment without removing application responsibility. ECS/Fargate needs a supported image and container compatibility; ECR stores that image. EKS adds Kubernetes operation and should follow a real requirement. With a maintained image and existing ECS capability, ECS/Fargate or Express Mode becomes more credible. Check build trust, image scanning/update, health, rolling deployment, data/schema compatibility, logging, IAM and underlying Fargate/load-balancer cost. App Runner is closed to new customers, so it is not a generic new-account option.
2. Shared editing requires supported file semantics and concurrency tests. S3 object access fits immutable key retrieval but is not a drop-in file share. EFS is a candidate for compatible shared Linux file access; an FSx offering may fit a Windows-specific file feature after exact protocol and feature checks. EBS is block storage with attachment/consistency constraints, not an automatic two-workstation share. Volume Gateway is a hybrid volume-interface candidate; validate cache, connectivity, write acknowledgment, upload/backup and failure recovery. Cost includes capacity, throughput/requests, network, copies, gateway runtime and operator time.
3. RDS preserves a relational direction only after version/extension/schema and application tests. Self-managed EC2 retains more database operations. DynamoDB needs a justified access model and rewrite of relational behavior. OpenSearch is a search projection, with source-to-index lag and rebuild. New independent key lookups may justify DynamoDB if synchronization, authority and cost are explicit. A row count alone cannot establish payment or booking meaning.
4. SQS fits work that one consumer group should process with durable retry; SNS and EventBridge fit different fan-out/routing contracts; Step Functions fits an explicit multi-step workflow. A transactional outbox can commit the booking and its publication obligation together when both belong to the same supported database transaction. A relay must still find and publish pending work; monitor and reconcile stuck obligations, and handle duplicate deliveries. Idempotency, ordering requirements and dead-letter triage protect business effects. Lambda versus container depends on measured runtime, dependencies, scaling, connection and cost. If finance requires the report in the response, a purely asynchronous report path violates the new contract unless that promise is renegotiated.
5. Measure the actual read bottleneck before adding state. ElastiCache is disposable acceleration and needs invalidation/failure handling. Aurora Serverless changes capacity management within its supported relational model; DynamoDB changes the data model and access contract. Compare capacity floors, spikes, requests, storage, backup, transfer, logs, overlap and labor using current regional inputs. Credits change payment timing, not resource consumption. A cheaper bill that fails correctness or recovery is not a valid winner.

For the acquisition transfer, look first for Windows file compatibility, cross-site access and recovery obligations. Preserve a clear ledger authority and rollback data direction while changing one seam at a time. Require representative client, failure and cost evidence before committing. The [local cutover drill](../migration-cutover/README.md) illustrates reconciliation and target-only writes; it does not execute the platform choices here.
