# Professional performance: assessor reasoning

These criteria evaluate fictional reasoning. They are not workload benchmarks, AWS prices, a calibrated exam key or a learner result.

1. The CPU average does not explain a long-tail booking delay when connection wait and errors rise. Inspect pool wait, active connections, query plan, database work and retry amplification before adding app workers; more callers may worsen a database bottleneck. With sustained 92% CPU and low dependency wait, profile the actual hot work and compare supported family/size candidates under the same peak input and success measure.
2. The controlled local lab shows eight synthetic source reads without coalescing and one with a shared per-key flight inside one process; a failed flight is not cached. Six processes can still produce six source calls, above the supplied allowance of four. Define a separate fleet-level admission or source protection path. Authorization must be checked for each caller before returning private bytes; one shared load is not one shared grant. Coalescing says nothing about latency, staleness or a selected cache service.
3. A 12-second-lag replica cannot meet an immediate read-after-write promise for that record merely because it reduces primary read work. Move that read to an authoritative path or revise the product promise with explicit status/freshness. An accidentally corrupted write may reach the replica; historical recovery and accepted-effect reconciliation require a separate point and evidence.
4. The supplied completion ceiling is min(20 worker, 8 store) = 8/s, so backlog grows by 4/s under 12/s arrival. With the store at 16/s, four spare completions/s drain 1,440 jobs in 360 seconds, or six minutes, under ideal steady conditions. A 20-minute outage adds work and may breach the deadline; recalculate using measured arrivals, retry volume, actual service-time distribution, warm-up, storage behavior and queue age.
5. Object storage fits immutable downloads; a POSIX writer needs a compatible shared-file interface or an application change; block storage is a different attached-volume contract. If the processor changes to object writes, test atomic publication, retry identity, read-after-write expectations, metadata, permissions, multipart/large-object behavior and recovery before removing the file dependency. Cost includes requests, transfer, retention, throughput and operational work.
6. Preserve one authoritative admission decision for the last slot. Analytical and search copies may answer different read questions, but their lag, indexing errors, security scope, recovery and cost become new obligations. A “purpose-built” service choice follows access pattern and correct business semantics, not a blanket performance claim.
7. High memory and low CPU suggest a memory constraint but network/disk wait are competing hypotheses. Compare supported family architecture and runtime compatibility; fix or isolate I/O and query causes where evidence warrants. A fair bounded trial holds inputs, success definition and peak/failure requirements constant, records customer latency and cost per successful job, and retains a compatible rollback. Do not turn a one-run local result into a universal EC2 recommendation.
8. The trace gives cacheable transfers the largest observed share, so test an HTTP delivery/cache hypothesis with CloudFront and measure browser p95, cache hit/miss cohorts, origin requests, byte transfer and correctness. A dynamic HTTP path needs its own cache policy; private responses must not leak across viewers. Global Accelerator addresses a different TCP/UDP endpoint-routing problem and does not cache assets or remove database wait. Do not promise a fixed latency reduction: geography, workload, endpoint health and current charges need a bounded comparison.
9. Tightly coupled EC2 communication can justify testing a cluster placement group because placement can reduce node-to-node network latency. The gain must be measured on the same job; a cluster lives within one Availability Zone and placement/capacity constraints affect recovery. More independent web replicas address request capacity or availability, not the supplied inter-node wait. A partition or spread placement strategy addresses correlated hardware failure in different workload shapes; it is not an interchangeable performance setting.

The business promise is a workload-level KPI and target. Define completed searches, the weekday window, source of timing, errors and correctness before calculating a percentage. Compare the baseline and trial by cohort, sample count, tail behavior, errors and cost; a change in traffic mix can mimic an improvement. The selected AWS service SLA is a separate contractual commitment under its current terms. Neither the fictional trial nor an AWS SLA proves the application's customer objective.

The [local cold-cache lab](../cold-cache-burst/README.md) demonstrates controlled concurrency only. Selected AWS performance, service eligibility, complete price, IAM, failure headroom and independent learner transfer remain unverified.
