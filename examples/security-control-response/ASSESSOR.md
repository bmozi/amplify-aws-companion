# Assessor reasoning: security control response

Read after an independent attempt. These are fictional changed conditions and not a calibrated exam score or AWS security assessment.

1. **Simulated allow:** The simulator evaluates the supplied policy/request context without sending a service request. Inspect the actual principal/session, action, resource, condition keys, resource policy and applicable boundaries/organization restrictions, plus the service response and any relevant audit event that was actually collected. A missing event requires a logging-scope check, not an invented record. Do not widen an identity policy just because one simulation said allow.
2. **Access Analyzer:** An external-access finding describes potential access relative to the analyzer's chosen zone of trust. It is not a download log. Review the resource policy and intended partner, then test allowed partner and unrelated principal requests under the effective controls. Confirm analyzer coverage and update timing.
3. **MFA:** MFA and federation protect staff sign-in and role assumption. They do not perform Alice-versus-Bob ownership checks in Maya's application. A real negative application request must deny Bob and avoid returning Alice's note; a positive Alice request must still work.
4. **Organization:** The proposed organization controls stay design-only for the single-account Free-plan learning sandbox. In a future authorized multi-account design, Identity Center can assign account roles, an SCP can set a ceiling for member-account principals, and IAM/resource policies still govern specific requests. An SCP is not a grant and does not replace application authorization.
5. **Trusted Advisor:** Record the exact check, result timestamp, account/resource and support-plan access. Basic Support has selected security checks and manual refresh, not every check or automatic update. Validate the current resource state and customer effect before a scoped change. A stale check should prompt inspection, not destructive correction.
6. **Config:** A conformance pack groups Config rules and possible remediations in a defined scope. Compliance of nine recorded resources cannot speak for the tenth outside recording/evaluation. Restore inventory/recorder coverage first, then evaluate the missing export and test the actual public/denied paths. A green rule is evidence of that evaluation, not a traffic firewall.
7. **Classification:** The public copy needs its own contents, owner, intended audience, approved publishing path and retention decision. Tags can record metadata, but access controls and application checks enforce the decision. Test an intended public read and a denied private read; find older copies and backups before claiming removal.
8. **KMS:** Encrypted bytes may be present while the recovery principal cannot decrypt or the key is unavailable. Verify permission and key path on a separate restored candidate, then application reads and booking correctness before reopening. A storage encryption flag alone does not prove recoverability.
9. **TLS:** The customer's actual endpoint, hostname, trust chain and validity determine the connection result. An ACM record can be unused or differ from the served certificate. Keep hostname verification; repair association/renewal or endpoint configuration. Rest encryption and TLS answer different locations in the data path.
10. **Secret rotation:** Confirm the supplier accepts the new value, each worker obtains it, and the old value is retired at the intended time. Test failure/rollback during overlap. A current version in a secret store is not evidence that all running callers refreshed or that the supplier changed.
11. **Findings:** Inspector reports a vulnerability in a scanned artifact, GuardDuty reports suspicious activity under its coverage, and a Security Hub control finding reports posture against that control. Join exact identities and event times before correlating. Confirm what image actually runs, which detectors/recorders cover each target, the bounded correction and a new assessment plus customer checks. A quiet dashboard can mean missing coverage.
12. **Missing object event:** The stipulated client response is evidence of a denied request from that client's perspective, subject to preserving its identity, destination and time. `GetObject` is an S3 object data event; CloudTrail Event History does not contain data events, and the case's trail did not select this bucket's object events. The empty search therefore cannot establish that no request occurred or identify the denying policy. Compare the sanitized response and available independent request evidence with the actual session and policy context; record the missing audit evidence rather than inventing an event. If future object logging is justified, design selectors, destination, access, retention, volume and price, then separately test a new authorized request and its delivery. Enabling logging later does not recreate an unrecorded past event. This paper case does not configure CloudTrail or establish an IAM decision.

The local companion tools exercise classification decisions, TLS trust/name rejection, generic credential overlap, fictional evidence joins and matrix bookkeeping. They do not implement IAM, threat detection, managed secrets or compliance in AWS.
