# Assessor notes — CDN strategy

There is no single required design. Grade the reasoning against the supplied promises and whether the answer names reversible evidence.

- **A — Public field guide:** CloudFront is a plausible candidate because content is reusable and users are geographically distributed. The prompt lacks a baseline; compare viewer latency and origin load before deciding to keep it. Measure the same representation, regions, time window and request mix. A CDN is not proven useful by geography alone.
- **B — Private invoice:** Reject a shared path-only cache for customer-specific responses. Start with caching disabled for the private behavior. Any later design needs authenticated viewer access, response-aware cache variation, and warm-cache tests showing customer B cannot receive customer A's invoice. A user-supplied key component does not authenticate a user.
- **C — Nearby dashboard:** Keeping the direct regional path is a valid provisional choice because the supplied service already meets its target and has no capacity issue. If adding an edge path, identify a newly measured requirement and price its requests, delivery, origin work, logs/security features and operations. “CDN is faster” is unsupported here.
- **D — Seat booking:** An edge path might help establish viewer connections or serve cacheable static assets. It does not atomically reserve a seat, enforce caller authority, resolve a lost response or establish global write ownership. Assess the write contract independently and never cache a mutation as a shortcut to correctness.
- **E — Safety notice:** A shorter TTL bounds ordinary freshness only within configured behavior and can increase origin requests. A versioned immutable path makes new approved content addressable; an old URL can still work until controlled. Invalidation is an operational action whose scope, progress and cost must be checked. None removes downloads or copies outside CloudFront. Require a withdrawal test and a stated stale-content promise.

Across all cases, a cache-hit ratio is a diagnostic, not the customer outcome. The learner should measure by geography and request class, inspect cache-key dimensions that actually change the response, distinguish origin-cached from uncached health, and compare current complete prices. Current CloudFront pricing offerings can change; this assessment has no rate table. No AWS distribution, cache behavior, request, bill, security proof or learner response is represented here.
