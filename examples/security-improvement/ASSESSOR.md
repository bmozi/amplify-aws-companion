# Assessor reasoning for the security-improvement packet

These are author examples for review after an attempt, not a learner result, legal opinion, effective-policy evaluation or AWS implementation receipt. A strong alternate answer may choose a different service or order if it proves the same bounded protections and recovery.

## Seven decisions

1. **Data lifetime:** P17 remains restricted inside the draft and downloadable PDF until an owner approves a sanitized exact version. Review embedded bytes, metadata, thumbnails and derived copies, not just the visible page. A data owner and applicable business/legal requirements establish retention and holds; the exercise does not supply a legal period. Keep a deletion/hold ledger available during restore and reconcile restored copies before reopening access.
2. **Least privilege:** A supplier session should reach only the approved object version through the selected principal, exact resource/key permissions and intended route. Permit the exact read and test denial for a neighboring object, unrelated key and role path. An S3 allow cannot grant KMS decrypt, and an IAM allow can be limited by applicable resource policy or deny. TLS proves the selected connection property, not record ownership. Effective access needs the actual request context and all relevant policy layers.
3. **Traceability:** Join role/session identity, account, Region, resource ARN/object key and version, request ID and event/observation times. Confirm which S3 data events and Regions were configured before treating absence as meaningful. The Inspector finding reports a vulnerability assessment for a named component; it does not prove exploitation. A Patch Manager compliant scan from 18 days ago is a stale point-in-time result, not proof of today's package or next image. [Patch Manager](https://docs.aws.amazon.com/systems-manager/latest/userguide/patch-manager.html) defines compliance against the selected baseline.
4. **Credentials:** Prove B at the supplier while A still works, publish B, test each worker's refreshed use, then retire A and explicitly reject it. The [local overlap round](../credential-rotation/README.md) exercises these generic steps with public fixture values and sequential loopback calls. If B fails, keep A and stop publication/retirement. Urgent compromise can require immediate A revocation, accepting a possible availability interruption while consumers refresh. Secrets Manager's [rotation function](https://docs.aws.amazon.com/secretsmanager/latest/userguide/rotate-secrets_lambda-functions.html) uses pending/current/previous stages; supported alternating-user database rotation is a distinct mechanism, not this arbitrary supplier's two-string contract.
5. **Patches:** Record the affected host/package/version and the baseline/approval status. Test a small eligible host or a new image and its application path before a broad wave. Patch the source of the next image and the application dependency separately; otherwise replacement can reintroduce the issue. A scanner finding alone does not authorize a fleet-wide install. Patch compliance cannot prove that every application library is safe, that a next image is fixed or that the business path still works.
6. **Backup:** Restore the specific retained copy with the key and identity that will be used in recovery. Verify confirmed bookings, writer authority, route and customer result; calculate RPO from the last durable confirmed point and RTO from the declared incident start to usable customer service. Reconcile approved deletions and holds before reopening a recovered copy. A catalog entry or successful decrypt alone is incomplete.
7. **Remediation:** Inspect the Config evaluation's account, Region, resource, timestamp and rule inputs. Do not enable a tag-wide mutation based on a test-bucket observation. Fence exact targets and exceptions, test one, check the actual state, and stop on uncertainty or unexpected effects. Evaluation, attempted action, successful API call and acceptable customer state are separate receipts.

## Changed facts

| Fact | Revised conclusion | Unchanged boundary |
| --- | --- | --- |
| Hidden address remains in embedded image | Do not publish that PDF; sanitize and re-review exact bytes. | A clean visible page is not proof of a safe download. |
| S3 narrowed, key/second role broad | Effective least privilege remains unproved; inspect and deny both alternate paths. | The approved exact-object read still needs a positive test. |
| Data events enabled today | Record future selected reads; investigate older reads through any other retained evidence, or report unknown. | A new trail cannot retroactively create missing historical events. |
| One worker retains A | Delay ordinary retirement until refresh/acceptance is proved; emergency revocation can choose security over availability with explicit impact. | One worker's success is not fleet coverage. |
| Host compliant, image/library old | Repair the next image and library, test replacement, and keep separate finding status. | Host baseline compliance is scoped and time-bound. |
| Restore revives deleted photo | Keep access closed, apply deletion/hold reconciliation and verify all copies before reopening. | Decryptability alone is not correct recovery. |
| Tag repair reaches held archive | Stop the action; narrow resource IDs and honor the hold/owner decision before any mutation. | A Config result does not authorize every tagged resource change. |

The packet maps the transitional task partially through explanation and changed-condition design. There is no live policy denial, Secrets Manager rotation, Patch Manager run, Config remediation, backup restore, independent technical review or learner transfer result. Organization-dependent controls remain design-only in this exercise.
