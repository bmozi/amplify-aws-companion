# Professional deployment choice: match the change to the work

This fictional design packet follows [Unit 03's upgrade-path lesson](../../reader/BOOK-LOCATORS.md#book-23a0a58cf6f824c1) and [E15](../../curriculum/EXERCISES.md#e15). No AWS service, pipeline, role, repository connection or paid runtime is created. Answer before reading the [assessor reasoning](ASSESSOR.md). For each case, record the business outcome, current platform and data, candidate change, service/operator responsibilities, IaC and artifact identity, build/test/approval gates, exposure and customer observation, rollback or roll-forward boundary, cost and cleanup, and the first fact that would change your choice.

1. **Add the private supplier call.** Maya's public repair website is hosted from a Git branch. A new feature calls a supplier using a private credential and may send a reminder later. Compare keeping the website on Amplify Hosting while adding a server-side API/workflow, moving the whole web service to ECS Express Mode from an image, and rebuilding an EC2 fleet. Which requirement, if any, forces a full migration? Where do image production, secret access, tenant authorization, durable retry and completed-message reconciliation belong? Do not assume App Runner is available to a new customer.
2. **The Friday upgrade.** The application is on EC2 with a hand-edited runtime. A security update is due, but the current image recipe omits a monitoring agent and the previous CodeDeploy stop hook sometimes fails. Compare an emergency in-place repair with building a tested replacement image and deploying the application revision. Name the exact deadline evidence, owner, test, fallback and post-incident reconciliation. Do not call a patch “immutable” merely because an AMI is eventually made.
3. **The managed-runtime surprise.** An existing App Runner customer has this app deployed from source. A teammate says AWS now owns all patching, compatibility and rollback. A runtime version update changes behavior; the old application artifact still expects a database column scheduled for removal. Decide which duties the service takes over and which the team retains. Compare a compatible image and ECS Express Mode migration with retaining the supported existing service during the transition. A new customer cannot choose App Runner; identify the image-build and operating work that moves to the team.
4. **The infrastructure preview.** A CloudFormation change set shows replacement of a stateful resource while the CI test suite passes. A teammate wants to execute immediately because both checks are green. Define a change-management decision record: data owner, impact, backup/restore, dependency graph, retention and cost, reviewer, stop condition and recovery. Which questions can the change set answer, and which require business-level tests?
5. **The rollback that cannot unsend.** A canary deployment sends 100 supplier messages, then a customer-level error gate rejects the candidate. The controller can route back to the old version. The candidate also wrote records that old code may not read. State the immediate traffic decision, compatibility check, message reconciliation and customer communication owner. Run the [local canary](../canary-release/README.md) and [schema compatibility lab](../schema-compatibility/README.md) to see their bounded behavior, then list the live facts still missing.
6. **The container option.** A team wants ECS on Fargate because it does not want to patch hosts. The service has long in-flight requests and a shared file write. Compare this with its current EC2 deployment: who owns image updates, health, draining, file authority and rollback? What local [container replacement drill](../container-release/README.md) would be useful, and why would passing it not prove ECS scheduler, networking or storage behavior?

Ask Codex to draw the artifact/controller/data boundary and to challenge the selected managed service with an untested customer or recovery requirement. Separate supplied facts, AWS documentation, local observations and unknowns. The paper cases do not establish professional exam readiness or live deployment.
