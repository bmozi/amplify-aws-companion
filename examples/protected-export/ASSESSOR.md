# A15 protected export assessor notes

Read only after recording your design. These are answer criteria for the stated fictional packet, not proof of live AWS permissions or of a learner's skill.

The smallest useful export is an approved **version** with part number and quantity, tied to a named recipient and purpose. A count or filename alone cannot establish that private columns were removed. A replacement needs a new content review. Withdrawal must distinguish blocking future reads from handling copies already delivered. The source records stay private regardless of export approval.

The [local continuation](README.md#run-the-version-and-copy-contract-locally) enforces a small application-owned contract: an invented version ID cannot be reused, a wrong digest or recipient cannot inherit approval, a changed version remains unapproved, and withdrawal blocks later owner reads without deleting the supplier's already copied bytes. It also checks a **supplied** actor name against the fixture's approval owner; because the name is trusted input, this is a decision-rule test, not authentication. The lab makes the **copy consequence** observable. It does not implement S3 policy, versioning, identity or KMS. In a real versioned general-purpose bucket, an explicitly versioned read calls for `s3:GetObjectVersion`; the unversioned current-object path uses `s3:GetObject`. Review both effective paths before claiming only the approved version is reachable. A local denial cannot substitute for the corresponding harmless AWS request under the intended role.

Direct read preserves owner control over future access to the owner's object but adds continuing bucket/key-policy and availability dependencies. Copying a minimized object to a recipient-controlled destination can make delivery less dependent on the source account after transfer, but adds another copy, recipient retention and deletion responsibilities, and cannot be recalled solely by changing the owner's bucket policy. A strong choice relates these tradeoffs to weekly cadence, recipient security, latency and contractual deletion evidence; neither choice is inherently compliant or universally cheapest.

Do not infer that A, B or C will return a particular AWS error string: the packet lacks complete live policy and request context. A negative result from a nonexistent object, invalid ARN or broken network path does not validate an authorization boundary. A KMS key grant alone does not authorize S3 reads; an S3 read grant alone does not authorize the stated KMS use. Optional endpoint/access-point restrictions are additional evaluation inputs, not automatic requirements for every export.

Cost reasoning must include storage and copies/versions, requests and retrieval/transfer, key and KMS requests, logs and any selected network or replication feature. A budget alert does not enforce a chosen run limit. Before a live exercise, choose limits appropriate to your account, estimate the whole run and verify current prices and credit eligibility. This paper exercise does not establish live cross-account behavior or measured billing.
